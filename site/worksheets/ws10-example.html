10.1

วางแผนโดเมนและตั้งค่า DNS

เลือกชื่อโดเมน

เกณฑ์ตัวอย่างที่ดีควรเลี่ยง
สั้น จำง่าย สะกดตามเสียงได้phukham.coffeephukhamcoffeeroasterschiangrai.com
ไม่มีขีดหรือตัวเลขที่ต้องอธิบายphukham.co.thphu-kham-2569.com
ตรงกับชื่อแบรนด์และบัญชีโซเชียล@phukham ทุกช่องทางชื่อเว็บกับเพจคนละชื่อ
ไม่ซ้ำเครื่องหมายการค้าของผู้อื่นตรวจที่กรมทรัพย์สินทางปัญญาก่อนจดชื่อคล้ายแบรนด์ดัง
นามสกุลเหมาะกับเงื่อนไขโดยสรุป
.comธุรกิจทั่วไป ลูกค้าหลายประเทศใครก็จดได้
.co.thบริษัทที่จดทะเบียนในไทยต้องใช้เอกสารนิติบุคคลหรือเครื่องหมายการค้า จดผ่านผู้รับจดที่ THNIC รับรอง
.in.thบุคคลทั่วไปหรือโครงการจดได้โดยไม่ต้องมีบริษัท
.ac.th .go.thสถานศึกษา หน่วยงานรัฐสำหรับหน่วยงานประเภทนั้นเท่านั้น

ร้านในตัวอย่างเป็นบริษัท จึงเลือก .co.th เป็นชื่อหลัก และจด .com ไว้ด้วยเพื่อกันคนอื่นจดชื่อเดียวกัน ตรวจเงื่อนไขล่าสุดกับผู้รับจดก่อนจดจริงเสมอ

ระเบียน DNS ที่ต้องตั้ง

หลังซื้อโฮสติ้ง ผู้ให้บริการจะแจ้ง IP ของเซิร์ฟเวอร์ (ตัวอย่างนี้ 203.0.113.10) แล้วเข้าหน้าจัดการ DNS ของผู้รับจดโดเมน เพิ่มระเบียนตามตาราง

ชนิดชื่อ (Name/Host)ค่า (Value/Points to)TTLความหมาย
A@203.0.113.103600phukham.example ไปที่ IPv4 ของโฮสติ้ง (@ คือตัวโดเมนเอง)
CNAMEwwwphukham.example.3600www.phukham.example เป็นชื่อเรียกอีกชื่อของโดเมนหลัก จึงตาม A Record ไปเอง
CNAMEshopphukham.myshopify.com. (ตัวอย่าง)3600ชี้ซับโดเมนไปที่บริการภายนอกที่ให้ชื่อมา
A RecordCNAME
ชี้ไปที่IP Address (ตัวเลข)ชื่อโดเมนอื่น
ใช้เมื่อรู้ IP ของเซิร์ฟเวอร์ และ IP ไม่เปลี่ยนบ่อยผู้ให้บริการให้เป็นชื่อ เช่น GitHub Pages, CDN
ใช้กับตัวโดเมนหลัก (@)ได้ไม่ได้ตามมาตรฐาน DNS เพราะชื่อที่มี CNAME ต้องไม่มีระเบียนอื่น แต่โดเมนหลักต้องมี NS และ SOA

TTL (Time To Live) คือจำนวนวินาทีที่เครื่องอื่นจำค่าเดิมไว้ 3600 คือ 1 ชั่วโมง การเปลี่ยน DNS จึงอาจยังไม่เห็นผลทันที หนังสือแนะนำให้เผื่อเวลา 24–48 ชั่วโมงเมื่อเปลี่ยน Name Server ก่อนย้ายเซิร์ฟเวอร์ ให้ลด TTL ลงก่อนล่วงหน้า

ตรวจผลด้วยคำสั่ง

โค้ด
# macOS / Linux
dig phukham.example A
dig www.phukham.example CNAME

# Windows (Command Prompt หรือ PowerShell)
nslookup phukham.example
nslookup -type=CNAME www.phukham.example

กรณีเผยแพร่ด้วย GitHub Pages (หัวข้อ 10.3.2) ให้ตั้ง CNAME ของ www ไปที่ ชื่อผู้ใช้.github.io และ A Record ของโดเมนหลักไปที่ IP ของ GitHub Pages ทั้ง 4 ตัว ซึ่งตรวจได้ด้วยคำสั่ง dig (รันจริงเมื่อ 19 พ.ย. 2569):

ข้อผิดพลาดที่พบบ่อย
เปิดโดเมนแล้วยังเป็นหน้าเว็บเก่าหรือหน้าที่จอดโดเมน
DNS ยังไม่กระจายครบ หรือเครื่องจำค่าเดิม ลองเปิดด้วยมือถือที่ปิด Wi-Fi หรือใช้ dig @1.1.1.1 เทียบ
ใส่ชื่อ www.phukham.example ในช่อง Name
ผู้ให้บริการส่วนใหญ่เติมชื่อโดเมนให้เอง จะกลายเป็น www.phukham.example.phukham.example ใส่แค่ www
ตั้ง CNAME ที่ @ แล้วบันทึกไม่ได้
ใช้ A Record ที่ @ แทน หรือใช้ระเบียน ALIAS/ANAME ถ้าผู้ให้บริการมี
ภาพหน้าจอที่ต้องแนบ
  • หน้าจัดการ DNS ที่มี A และ CNAME (ถ้าไม่มีโดเมนจริง ให้ส่งตาราง DNS ที่วางแผนไว้)
  • ผลคำสั่ง nslookup หรือ dig
10.2

อัปโหลดเว็บไซต์และฐานข้อมูล

1. เตรียมไฟล์ก่อนอัปโหลด

ตรวจเหตุผล
ไม่อัปโหลด .git, node_modules, ไฟล์ .sql สำรอง, data/users.jsonไฟล์เหล่านี้ไม่ใช่ส่วนของเว็บ และบางไฟล์มีข้อมูลลับ
ชื่อไฟล์และโฟลเดอร์เป็นตัวพิมพ์เล็กทั้งหมด ตรงกับที่อ้างในโค้ดเซิร์ฟเวอร์ Linux แยกตัวพิมพ์ใหญ่เล็ก ไฟล์ที่เปิดได้บน Windows อาจขึ้น 404 (ใบงานที่ 3)
ลิงก์ใช้ path สัมพัทธ์เว็บอาจอยู่ในโฟลเดอร์ย่อยบนเซิร์ฟเวอร์
ปิด display_errorsไม่ให้ข้อความผิดพลาดเปิดเผยโครงสร้างไฟล์และฐานข้อมูล

2. ส่งไฟล์ด้วย FileZilla (SFTP)

  1. ติดตั้ง FileZilla Client จาก filezilla-project.org (เลือกตัวติดตั้งที่ไม่มีโปรแกรมแถม)
  2. File › Site Manager › New site · Protocol: SFTP - SSH File Transfer Protocol · Host: ชื่อเซิร์ฟเวอร์ · Port: 22 · Logon Type: Ask for password · User: ชื่อผู้ใช้ตามภาคผนวก จ หรือที่โฮสติ้งแจ้ง
  3. กด Connect ครั้งแรกจะถามยืนยัน Host key ให้ตรวจลายนิ้วมือกับที่ผู้ดูแลแจ้งก่อนกด OK
  4. ด้านซ้ายเป็นเครื่องเรา ด้านขวาเป็นเซิร์ฟเวอร์ เปิดโฟลเดอร์ปลายทาง (เช่น public_html หรือโฟลเดอร์ที่ภาคผนวก จ กำหนด) แล้วลากไฟล์จากซ้ายไปขวา
  5. ดูแท็บ Failed transfers ด้านล่างว่าต้องเป็น 0

เลือก SFTP ไม่ใช้ FTP ธรรมดา เพราะ FTP ส่งรหัสผ่านและไฟล์แบบไม่เข้ารหัส สิทธิ์ไฟล์ที่ใช้ทั่วไปบนโฮสติ้ง: โฟลเดอร์ 755 ไฟล์ 644 (คลิกขวา › File permissions ใน FileZilla) โฟลเดอร์ uploads ต้องให้เว็บเซิร์ฟเวอร์เขียนได้ ถ้าอัปโหลดรูปไม่ได้ให้สอบถามผู้ดูแลโฮสติ้งก่อนเปลี่ยนเป็น 777

3. ย้ายฐานข้อมูล (หัวข้อ 10.3.1)

  1. phpMyAdmin บนเครื่อง › เลือก phukham_shop › Export › Quick › SQL › Export
  2. แผงควบคุมโฮสติ้ง › MySQL Databases: สร้างฐานข้อมูล สร้างผู้ใช้ และ Add User To Database ให้สิทธิ์
  3. phpMyAdmin บนโฮสติ้ง › เลือกฐานข้อมูลที่สร้าง › Import › เลือกไฟล์ .sql › Import
  4. แก้ includes/db.php บนเซิร์ฟเวอร์เป็นค่าของโฮสติ้ง

includes/db.php (บนโฮสติ้ง)

โค้ด

10.3

เปิดใช้ HTTPS

ติดตั้งใบรับรองฟรี

วิธีทำอย่างไรข้อควรรู้
Let's Encrypt ผ่านแผงควบคุมcPanel: SSL/TLS Status › Run AutoSSL · DirectAdmin: SSL Certificates › Free & automatic certificate from Let's Encryptใบรับรองมีอายุ 90 วัน ระบบต่ออายุให้อัตโนมัติ
Cloudflareย้าย Name Server ไป Cloudflare เปิด Proxy (เมฆสีส้ม) แล้วตั้ง SSL/TLS เป็น Full (strict)ต้องมีใบรับรองบนเซิร์ฟเวอร์ด้วย ห้ามใช้โหมด Flexible คู่กับการบังคับ HTTPS ใน .htaccess เพราะจะเกิด ERR_TOO_MANY_REDIRECTS

ตรวจใบรับรองของเซิร์ฟเวอร์รายวิชา (รันจริง 19 พ.ย. 2569)

โค้ด
$ curl -s -o /dev/null -w "%{http_code} -> %{redirect_url}\n" http://fms.pnu.ac.th/lessons/
301 -> https://fms.pnu.ac.th/lessons/

$ echo | openssl s_client -connect fms.pnu.ac.th:443 -servername fms.pnu.ac.th 2>/dev/null \
    | openssl x509 -noout -subject -issuer -dates
subject=CN=fms.pnu.ac.th
issuer=C=US, O=Let's Encrypt, CN=YE1
notBefore=Oct 30 16:01:18 2026 GMT
notAfter=Jan 28 16:01:17 2027 GMT
ค่าที่ได้อ่านว่า
301 → https://…เปิดด้วย http:// แล้วเซิร์ฟเวอร์ส่งต่อไป https:// อัตโนมัติ
subject=CN=fms.pnu.ac.thใบรับรองออกให้ชื่อนี้ ตรงกับโดเมนที่เปิด
issuer=Let's Encryptใบรับรองฟรีจาก Let's Encrypt
30 ต.ค. 2569 – 28 ม.ค. 2570อายุ 90 วันตามแบบของ Let's Encrypt
Protocol TLSv1.3ใช้โปรโตคอลรุ่นล่าสุด

ในเบราว์เซอร์: คลิกไอคอนหน้า URL › Connection is secure › Certificate is valid จะเห็นข้อมูลชุดเดียวกัน

บังคับ HTTPS และปรับเซิร์ฟเวอร์ด้วย .htaccess

ใช้เมื่อโฮสติ้งยังไม่ได้บังคับให้ ไฟล์นี้ทดสอบกับ Apache 2.4.66 แล้ว: เปิดด้วย http ได้ 301 ไป https, ไฟล์ CSS ส่งแบบ gzip และมี Cache-Control 7 วัน, ส่ง Security Headers ทั้ง 3 ตัว และเปิดไฟล์ .sql ได้ 403

.htaccess

โค้ด
# .htaccess สำหรับเว็บไซต์ที่ขึ้นโฮสติ้งจริงแล้ว (Apache 2.4)

# 1) บังคับใช้ HTTPS: ส่งทุกคำขอ http:// ไป https:// ด้วยรหัส 301
RewriteEngine On
RewriteCond %{HTTPS} !=on
RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]

# 2) บีบอัดไฟล์ข้อความก่อนส่ง (ช่วยคะแนน Performance)
<IfModule mod_deflate.c>
  AddOutputFilterByType DEFLATE text/html text/css text/javascript application/javascript application/json image/svg+xml
</IfModule>

# 3) ให้เบราว์เซอร์เก็บไฟล์ไว้ใช้ซ้ำ (Browser Caching)
<IfModule mod_expires.c>
  ExpiresActive On
  ExpiresByType image/webp "access plus 1 month"
  ExpiresByType image/jpeg "access plus 1 month"
  ExpiresByType image/png  "access plus 1 month"
  ExpiresByType text/css   "access plus 1 week"
  ExpiresByType text/javascript "access plus 1 week"
</IfModule>

# 4) Security Headers (ช่วยคะแนน Best Practices)
<IfModule mod_headers.c>
  Header always set X-Content-Type-Options "nosniff"
  Header always set X-Frame-Options "SAMEORIGIN"
  Header always set Referrer-Policy "strict-origin-when-cross-origin"
</IfModule>
