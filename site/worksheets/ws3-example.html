ตรวจกับโจทย์ทีละข้อ

สิ่งที่โจทย์กำหนดอยู่ตรงไหนในโค้ด
<!DOCTYPE html>บรรทัดแรก บอกเบราว์เซอร์ว่าเป็น HTML5
lang และ charset UTF-8<html lang="th"> และ <meta charset="UTF-8"> ช่วยให้โปรแกรมอ่านหน้าจออ่านภาษาไทยถูกต้องและอักษรไทยไม่เพี้ยน
<h1>–<h6>h1 ชื่อ › h2 ข้อมูลการศึกษา › h3 มหาวิทยาลัย › h4 รายวิชาที่ชอบ › h5 วิชาที่ชอบที่สุด › h6 สิ่งที่อยากทำได้ (มี h1 เพียงตัวเดียว)
ย่อหน้า<p> ทุกข้อความเนื้อหา
<ul> / <ol>ul รายวิชาที่ชอบ (ไม่มีลำดับ) · ol เป้าหมาย (เรียงลำดับความสำคัญ)
<a>ลิงก์สัมพัทธ์ news.html schedule.html และลิงก์สัมบูรณ์ไป MDN
<img> + alt + เส้นทางสัมพัทธ์src="images/profile.jpg" alt บอกว่าในภาพมีอะไร ไม่ใช่แค่คำว่า "รูปภาพ" ใส่ width/height กันหน้ากระตุกตอนโหลด
ข้อผิดพลาดที่พบบ่อย
ใช้ / นำหน้า เช่น src="/images/profile.jpg"
/ นำหน้าคือเริ่มจากรากของเว็บไซต์ ไม่ใช่โฟลเดอร์ปัจจุบัน ถ้าเว็บอยู่ใน localhost/ws3/ รูปจะหาไม่เจอ ให้ใช้ images/profile.jpg
ใช้เส้นทางในเครื่อง เช่น C:\Users\...\profile.jpg
เปิดในเครื่องตัวเองได้ แต่เครื่องอื่นและเซิร์ฟเวอร์จะไม่เจอไฟล์
ชื่อไฟล์ Profile.JPG แต่เขียน profile.jpg
Windows ไม่สนตัวพิมพ์ใหญ่เล็ก แต่เซิร์ฟเวอร์ Linux สนใจ ให้ตั้งชื่อไฟล์เป็นตัวพิมพ์เล็กทั้งหมดและไม่มีช่องว่าง
เลือกหัวเรื่องตามขนาดตัวอักษร
h1–h6 บอกลำดับโครงสร้าง ไม่ใช่ขนาด ถ้าอยากได้ตัวเล็กลงให้ปรับด้วย CSS ภายหลัง
3.1

โครงสร้างเชิงความหมาย (Semantic Layout)

ส่วนที่ 2 · สัปดาห์ 4
<header> ชื่อเว็บ
<nav> เมนูหลัก
<main>
<article> ข่าว 1 ชิ้น
<header> หัวข่าว + วันที่
<section> รายละเอียด
<section> สิ่งที่กรรมการชื่นชม
<figure> ภาพ + คำบรรยาย
<aside> ข่าวที่เกี่ยวข้อง
<footer> ลิขสิทธิ์

เลือกแท็กอย่างไร

  • <article> เนื้อหาที่ยกไปอ่านที่อื่นได้ครบในตัว เช่น ข่าว 1 ชิ้น โพสต์ 1 โพสต์
  • <section> ส่วนย่อยที่มีหัวข้อของตัวเอง ถ้าไม่มีหัวข้อ มักควรเป็น <div>
  • <aside> เนื้อหาเสริมที่ตัดออกแล้วเรื่องหลักยังสมบูรณ์
  • <main> มีได้ 1 ตัวต่อหน้า และไม่อยู่ใน header, nav, aside หรือ footer
  • <header> ใช้ซ้ำได้ ทั้งส่วนหัวของหน้าและส่วนหัวของ article
  • โปรแกรมอ่านหน้าจอใช้แท็กเหล่านี้เป็นจุดกระโดด (landmark) ผู้ใช้กดข้ามไปที่ main หรือ nav ได้ทันที

3.2

ตารางข้อมูล (Table)

ตารางเรียนที่มีทั้งหัวคอลัมน์ (เวลา) และหัวแถว (วัน) จึงใช้ <th> ทั้งสองแบบและระบุ scope ให้โปรแกรมอ่านหน้าจอรู้ว่าเซลล์ไหนเป็นหัวของอะไร มีการรวมเซลล์ด้วย colspan และ rowspan

schedule.html

โค้ด
<!DOCTYPE html>
<html lang="th">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>ตารางเรียน ภาคเรียนที่ 2/2569</title>
  <style>
    table { border-collapse: collapse; }
    th, td { border: 1px solid #666; padding: 6px 10px; text-align: center; }
    caption { font-weight: bold; margin-bottom: 6px; }
  </style>
</head>
<body>
  <table>
    <caption>ตารางเรียน ภาคเรียนที่ 2 ปีการศึกษา 2569 (สมหญิง ใจดี)</caption>
    <thead>
      <tr>
        <th scope="col">วัน</th>
        <th scope="col">08:30–10:30</th>
        <th scope="col">10:30–12:30</th>
        <th scope="col">12:30–13:30</th>
        <th scope="col">13:30–16:30</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <th scope="row">จันทร์</th>
        <td colspan="2">การเขียนโปรแกรมบนเว็บ (ทฤษฎี)<br>ห้อง 3201</td>
        <td rowspan="5">พักกลางวัน</td>
        <td>การเขียนโปรแกรมบนเว็บ (ปฏิบัติ)<br>ห้องคอมพิวเตอร์ 2</td>
      </tr>
      <tr>
        <th scope="row">อังคาร</th>
        <td>ระบบฐานข้อมูล</td>
        <td>ภาษาอังกฤษเพื่อการสื่อสาร</td>
        <td>ว่าง</td>
      </tr>
      <tr>
        <th scope="row">พุธ</th>
        <td colspan="2">การออกแบบส่วนต่อประสานผู้ใช้</td>
        <td>กิจกรรมชมรม</td>
      </tr>
      <tr>
        <th scope="row">พฤหัสบดี</th>
        <td>สถิติเบื้องต้น</td>

      </tr>
      <tr>
        <th scope="row">ศุกร์</th>
        <td colspan="2">ว่าง</td>
        <td>พบอาจารย์ที่ปรึกษา</td>
      </tr>

แท็ก / Attributeหน้าที่
<caption>ชื่อตาราง ต้องเป็นลูกตัวแรกของ table ทันที
<thead> / <tbody>แยกส่วนหัวกับเนื้อหา เวลาพิมพ์ตารางยาวหลายหน้า เบราว์เซอร์จะพิมพ์ thead ซ้ำให้ทุกหน้า
<th scope="col">หัวคอลัมน์ (เวลา)
<th scope="row">หัวแถว (วัน) อ่านเป็น "จันทร์, 13:30–16:30: การเขียนโปรแกรมบนเว็บ (ปฏิบัติ)"
colspan="2"วิชา 4 ชั่วโมงกินพื้นที่ 2 ช่วงเวลา
rowspan="5"ช่วงพักกลางวันรวม 5 วันเป็นช่องเดียว แถวถัดไปจึงมี td น้อยลง 1 ช่อง
ข้อผิดพลาดที่พบบ่อย
จำนวนช่องในแต่ละแถวไม่เท่ากัน
นับ colspan และเซลล์ที่ถูก rowspan จากแถวบนครอบไว้ด้วย ทุกแถวต้องรวมได้ 5 คอลัมน์ W3C Checker จะเตือนถ้าตารางไม่ครบ
ใช้ border="1" บนแท็ก table
เป็น attribute แบบเก่า ให้ใส่เส้นด้วย CSS แทน
ใช้ตารางจัดเลย์เอาต์หน้าเว็บ
ตารางใช้กับข้อมูลแบบแถวและคอลัมน์เท่านั้น การจัดหน้าใช้ CSS Flexbox หรือ Grid (บทที่ 4)

แบบฟอร์มสมัครงาน (Interactive Form)

ทุกช่องมี <label for> ที่ตรงกับ id ของช่องนั้น กลุ่ม Radio และ Checkbox ครอบด้วย <fieldset> และ <legend> ให้รู้ว่าตัวเลือกเป็นคำตอบของคำถามอะไร

โค้ด

<body>

      <label for="fullname">ชื่อ–นามสกุล *</label><br>
      <input type="text" id="fullname" name="fullname" required
             pattern="[ก-๙A-Za-z ]{4,60}" autocomplete="name"
             title="ภาษาไทยหรืออังกฤษ 4–60 ตัวอักษร">
    </p>
    <p>

    </p>

Regex ที่ใช้ใน pattern

ช่องpatternความหมาย
ชื่อ–นามสกุล[ก-๙A-Za-z ]{4,60}อักษรไทย อังกฤษ หรือเว้นวรรค 4–60 ตัว
โทรศัพท์0[689][0-9]{8}ขึ้นต้น 0 ตัวที่สองเป็น 6, 8 หรือ 9 ตามด้วยตัวเลข 8 ตัว รวม 10 หลัก
รหัสผ่าน(?=.*[A-Za-z])(?=.*[0-9]).{8,}ต้องมีตัวอักษรอังกฤษอย่างน้อย 1 ตัว ตัวเลขอย่างน้อย 1 ตัว และยาวอย่างน้อย 8 ตัว

pattern ใน HTML ตรวจทั้งข้อความเสมอ ไม่ต้องใส่ ^ และ $ เอง และเบราว์เซอร์รุ่นใหม่ตีความ pattern แบบเข้มงวด (โหมด v) ถ้าต้องการขีด - เป็นตัวอักษรในวงเล็บ [ ] ต้องเขียน \- เสมอ

ผลการทดสอบที่ควรได้

กรอกผลที่ควรได้
เว้นชื่อว่างแล้วกดส่งส่งไม่ได้ เบราว์เซอร์ชี้ไปที่ช่องแรกที่ว่าง (required)
ชื่อ Tom123ไม่ผ่าน มีตัวเลข เบราว์เซอร์แสดงข้อความจาก title
อีเมล somying.example.comไม่ผ่าน ไม่มี @ (type="email" ตรวจเอง)
โทรศัพท์ 021234567ไม่ผ่าน มี 9 หลักและขึ้นต้น 02
โทรศัพท์ 0812345678ผ่าน
รหัสผ่าน abcdefghไม่ผ่าน ไม่มีตัวเลข
รหัสผ่าน web2569okผ่าน
ไม่เลือกรูปแบบการทำงานไม่ผ่าน ใส่ required ที่ radio ตัวใดตัวหนึ่งในกลุ่มก็พอ
ไม่ติ๊กยินยอมไม่ผ่าน checkbox ที่มี required ต้องติ๊กก่อนส่ง
ข้อควรรู้: การตรวจด้วย required และ pattern ช่วยผู้ใช้กรอกถูกต้อง แต่ไม่ใช่การป้องกันความปลอดภัย ผู้ใช้ปิดการตรวจฝั่งเบราว์เซอร์ได้ ฝั่งเซิร์ฟเวอร์ต้องตรวจซ้ำเสมอ (บทที่ 7)
ภาพหน้าจอที่ต้องแนบ
  • แบบฟอร์มที่กรอกครบ
  • ข้อความเตือนของเบราว์เซอร์เมื่อกรอกเบอร์โทรผิดรูปแบบ
  • ข้อความเตือนเมื่อเว้นช่องที่ required

ตรวจคำตอบของ AI ก่อนเชื่อ

  • AI อาจอ้างเลข WCAG ผิด ตรวจกับ WCAG 2.2 Quick Reference ทุกข้อ
  • AI มักใส่ alt ให้ทุกภาพ แม้ภาพตกแต่งที่ควรใช้ alt="" คนที่รู้ว่าภาพมีหน้าที่อะไรต้องตัดสินใจเอง
  • AI อาจแก้ข้อความภาษาไทยหรือเพิ่ม ARIA เกินจำเป็น ใช้แท็ก HTML ที่ถูกต้องก่อน ARIA เสมอ
  • คะแนน Lighthouse 100 ไม่ได้แปลว่าเข้าถึงได้ครบ ต้องลองใช้งานด้วยแป้นพิมพ์เองด้วย
