ภาษา HTML
และ HTML5

แท็ก เอลิเมนต์ ตาราง แบบฟอร์ม สื่อมัลติมีเดีย แท็กเชิงความหมาย การตรวจข้อมูลในฟอร์ม และการใช้ AI ช่วยตรวจโค้ด

ดร.สุรเชษฐ์ สังขพันธ์ · กด → หรือ Space ไปสไลด์ถัดไป · กด O ดูสารบัญ

ภาพประกอบในสไลด์ชุดนี้สร้างด้วย SVG/CSS โดยใช้ปัญญาประดิษฐ์ (AI) ช่วยสร้างพ.ศ. 2569

เป้าหมายของบทนี้

เรียนจบบทนี้ นักศึกษาจะ...

  • แยก แท็ก เอลิเมนต์ และแอตทริบิวต์ได้
  • เขียนโครงหน้า HTML5 ที่ถูกต้องตามมาตรฐาน
  • สร้างตาราง แบบฟอร์ม และใส่สื่อมัลติมีเดีย
  • วางโครงหน้าด้วยแท็กเชิงความหมาย (Semantic)
  • ใช้ AI ช่วยสร้างและตรวจโค้ด แล้วตรวจซ้ำเองได้

ผลลัพธ์การเรียนรู้ (CLO) ของบทนี้

CLO1 อธิบายแนวคิด องค์ประกอบ โครงสร้าง และหลักการออกแบบเว็บไซต์ได้อย่างถูกต้อง

CLO2 วิเคราะห์ความต้องการของผู้ใช้ และจัดทำขอบเขตงานและโครงสร้างเว็บไซต์ให้สอดคล้องกับโจทย์

CLO3 ใช้ภาษาและเครื่องมือในการพัฒนาเว็บไซต์ให้ทำงานได้ตามข้อกำหนด

CLO5 ประยุกต์ความรู้พัฒนาเว็บไซต์แก้ปัญหาจากสถานการณ์ พร้อมทดสอบและปรับปรุง

3.2 เอลิเมนต์ (Element) และแท็ก (Tag) (Duckett, 2011; บัญชา ปะสีละเตสัง, 2565ข)

หนึ่งบรรทัด มีหลายส่วน

<a href="https://www.pnu.ac.th">ม.นราธิวาสฯ</a>

กดปุ่มด้านบน หรือชี้ที่โค้ด เพื่อดูว่าแต่ละส่วนคืออะไร

Void

มีแท็กเปิดอย่างเดียว เช่น <br> <hr> <img>

Raw Text

เนื้อหาเป็นโค้ดล้วน เช่น <script> <style>

Nested

มีเอลิเมนต์อื่นซ้อนข้างใน เช่น <ul><li>...</li></ul>

3.3 รูปแบบมาตรฐานของ HTML · 3.4 HTML5

โครงหน้าที่ทุกไฟล์ต้องมี

ชี้ที่แต่ละบรรทัด

เพื่อดูหน้าที่ของบรรทัดนั้น

HTML 4 ต้องเขียน DOCTYPE ยาวและอ้าง DTD ส่วน HTML5 เหลือแค่ <!DOCTYPE html>

3.5 เริ่มต้นด้วยแท็ก <h1>

หัวเรื่องมี 6 ระดับ ใช้ตามลำดับความสำคัญ

  • หนึ่งหน้าควรมี <h1> เดียว คือชื่อหลักของหน้า
  • ไม่ข้ามระดับ เช่น h2 แล้วกระโดดไป h5
  • อย่าใช้ h เพียงเพราะอยากได้ตัวใหญ่ ใช้ CSS แทน

3.6 แท็กเดี่ยว (Void Elements)

ไม่มีเนื้อหา จึงไม่มีแท็กปิด

3.7 แท็กคู่ (Paired Tags)

แก้โค้ดทางซ้าย แล้วกด "ลองรัน"

3.8 แท็กตาราง (Table Tags)

ตาราง = แถว (tr) × ช่อง (th/td)

3.9 แท็กแบบฟอร์ม

ช่องรับข้อมูลแต่ละแบบ ลองกรอกได้เลย

ทุกช่องควรมี <label for="..."> จับคู่กับ id เพื่อให้คลิกที่ป้ายแล้วเลือกช่องได้ และโปรแกรมอ่านหน้าจออ่านถูก

3.9 action และ method ของแบบฟอร์ม

ข้อมูลเดินทางไปเซิร์ฟเวอร์อย่างไร

3.10 แท็กมัลติมีเดียและกราฟิกใน HTML5

เล่นสื่อและวาดภาพได้โดยไม่ต้องใช้ปลั๊กอิน

<video src="intro.mp4" controls width="480" poster="cover.jpg"></video> <audio src="song.mp3" controls></audio> <canvas id="pad" width="520" height="300"></canvas> <iframe src="https://www.youtube.com/embed/..." title="วิดีโอ"></iframe>
  • controls แสดงปุ่มเล่น หยุด เสียง
  • ใส่คำบรรยาย (subtitle) ด้วย <track>
  • ใช้เฉพาะสื่อที่มีสิทธิ์เผยแพร่

ลองวาดบน <canvas> ด้วยเมาส์หรือนิ้ว (JavaScript สั่งวาด)

3.11 ทำไมต้องใช้แท็กเชิงความหมาย

3.12 Native Form Validation

ให้เบราว์เซอร์ช่วยตรวจก่อนส่ง

ผลการตรวจ

กรอกแล้วกด "ส่ง"

สำคัญ: การตรวจฝั่งเบราว์เซอร์ช่วยผู้ใช้ แต่ผู้ไม่หวังดีปิดได้ จึงต้องตรวจซ้ำฝั่งเซิร์ฟเวอร์ด้วย PHP เสมอ (บทที่ 7)

3.13 AI-Assisted HTML Development (W3C, 2024; OWASP, 2023b)

สั่ง AI ให้ชัด แล้วตรวจผลด้วยเครื่องมือมาตรฐาน

บทบาท: ผู้เชี่ยวชาญ HTML5 และการเข้าถึงเว็บ (WCAG) งาน: ตรวจโค้ด HTML ด้านล่าง ให้ตรวจ: 1) ใช้แท็กเชิงความหมายเหมาะสมหรือไม่ 2) ทุก <img> มี alt และทุกช่องฟอร์มมี <label> 3) ลำดับหัวเรื่อง h1–h6 ถูกต้อง ผลลัพธ์: ตารางปัญหา บรรทัด วิธีแก้ [วางโค้ดที่นี่ ไม่วางข้อมูลส่วนบุคคลจริง]

ตัวอย่างกรอบคำสั่งจากหัวข้อ 3.13.4

ข้อควรระวัง (3.13.3)

  • AI อาจใช้แท็กหรือแอตทริบิวต์ที่เลิกใช้แล้ว
  • อาจลืม alt, label หรือใส่ลำดับหัวเรื่องผิด
  • ต้องตรวจด้วย W3C Validator และ Lighthouse ซ้ำ
  • อ่านเข้าใจทุกบรรทัดก่อนส่งงาน และบันทึกการใช้ AI
W3C Nu Html Checkerตรวจความถูกต้องของ HTML Lighthouseตรวจการเข้าถึงใน Chrome DevTools OWASP HTML5 Securityข้อควรระวังด้านความปลอดภัย

HTML คือโครงกระดูกของทุกหน้าเว็บ

  • เอลิเมนต์ = แท็กเปิด + เนื้อหา + แท็กปิด และมีแอตทริบิวต์เสริม
  • HTML5 เริ่มด้วย <!DOCTYPE html> มี head และ body
  • ตารางใช้ tr/th/td ฟอร์มต้องมี label และเลือก GET/POST ให้เหมาะ
  • แท็กเชิงความหมายช่วย SEO และการเข้าถึง
  • ตรวจในเบราว์เซอร์แล้ว ต้องตรวจซ้ำที่เซิร์ฟเวอร์ · AI ช่วยได้แต่ต้องตรวจ
