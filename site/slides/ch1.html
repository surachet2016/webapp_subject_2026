บทที่ 1 แนวคิดและหลักการออกแบบเว็บไซต์

เริ่มด้วยคำถาม

ผู้ใช้ตัดสินใจภายในไม่กี่วินาที

ลองดูหน้าเว็บทางขวา 5 วินาที แล้วตอบว่า

  • เว็บนี้เกี่ยวกับอะไร
  • ปุ่มที่ควรกดคืออะไร
  • รู้สึกน่าเชื่อถือไหม

เปรียบเทียบสองแบบ: สิ่งที่ต่างคือลำดับสายตา ช่องว่าง สี และความชัดเจนของปุ่ม

1.1 องค์ประกอบหลักของหน้าเว็บไซต์

แยกชั้นหน้าเว็บให้เห็นเป็น 3 มิติ

  • Header โลโก้ ชื่อเว็บ เมนูหลัก บอกว่า "อยู่ที่ไหน"
  • Navigation เส้นทางไปส่วนต่าง ๆ
  • Body เนื้อหา ภาพ ฟอร์ม ปุ่ม CTA
  • Footer ลิขสิทธิ์ ติดต่อ นโยบาย ลิงก์โซเชียล

ใน HTML5 ใช้แท็ก <header> <nav> <main> <footer> ตรงกับชั้นเหล่านี้ (บทที่ 3)

กิจกรรม 5 นาที: เลือก 1 เว็บ แล้วบอกเพื่อนว่า Header, เมนู, ปุ่มหลัก และ Footer อยู่ตรงไหน และอะไรทำให้ใช้ง่าย

1.4.1 การจัดระเบียบสายตา (Visual Hierarchy)

การใช้สีที่ถูกต้อง

เลือกสีหลัก แล้วให้ระบบสร้างชุดสี

  • 60-30-10: พื้นหลัง 60% สีรอง 30% สีเน้น 10%
  • ใช้สีบอกความหมาย: เขียว=สำเร็จ แดง=ผิดพลาด
  • อย่าใช้สีอย่างเดียวบอกข้อมูล ให้มีข้อความหรือไอคอนด้วย

ข้อความหัวเรื่อง

ตัวอย่างเนื้อหาภาษาไทยสำหรับทดสอบการอ่าน นักศึกษาลองเปลี่ยนสีทางซ้ายแล้วดูว่าอ่านง่ายขึ้นหรือยากขึ้น

เครื่องมือจริง: WebAIM Contrast Checker

การใช้ฟอนต์ (Typography)

ฟอนต์ภาษาไทยบนเว็บต้องอ่านง่ายก่อนสวย

  • เนื้อหาภาษาไทยควร 16 px ขึ้นไป ระยะบรรทัดประมาณ 1.5–1.8
  • ใช้ไม่เกิน 2 ตระกูลฟอนต์ ต่างกันด้วยขนาดและน้ำหนัก
  • โหลดเฉพาะน้ำหนักที่ใช้ และตรวจสิทธิการใช้ฟอนต์

การออกแบบเว็บไซต์เพื่อผู้ใช้

เว็บไซต์ที่ดีช่วยให้ผู้ใช้ทำงานสำเร็จได้รวดเร็ว ตัวอักษรที่อ่านง่าย ระยะห่างที่พอดี และความยาวบรรทัดที่เหมาะสม ทำให้ผู้ใช้อ่านเนื้อหาได้นานโดยไม่ล้าสายตา ภาษาไทยมีสระและวรรณยุกต์ซ้อนบนล่าง จึงต้องการระยะบรรทัดมากกว่าภาษาอังกฤษ

1.6.2 มาตรฐาน WCAG 2.2 (W3C, 2023)

เว็บที่ทุกคนใช้ได้: หลัก POUR

P รับรู้ได้

ภาพมี alt คำบรรยายวิดีโอ สีตัดกันพอ

O ใช้งานได้

ใช้คีย์บอร์ดได้ เห็นกรอบโฟกัส ไม่มีเวลาบีบคั้น

U เข้าใจได้

ภาษาชัด เมนูอยู่ที่เดิม ข้อความแจ้งข้อผิดพลาดบอกวิธีแก้

R รองรับได้

HTML ถูกมาตรฐาน ใช้ได้กับโปรแกรมอ่านหน้าจอ

ลองเลย: กดปุ่ม Tab บนคีย์บอร์ดตอนนี้ แล้วดูว่ามีกรอบโฟกัสที่ลิงก์หรือปุ่มไหม → อ่านมาตรฐาน WCAG ที่ W3C

แอนิเมชันที่สวยและมีความหมาย

แอนิเมชันต้องช่วยผู้ใช้ ไม่ใช่แค่สวย

Hover / Feedback

ชี้ที่การ์ดนี้ การยกตัวบอกว่ากดได้ ใช้เวลา 150–300 ms

Skeleton Loading

บอกว่ากำลังโหลด ลดความรู้สึกว่ารอนาน

3D Transform

CSS 3D ใช้ดึงความสนใจได้ แต่ใช้แต่พอดี

  • เคารพผู้ใช้ที่ตั้งค่าลดการเคลื่อนไหว ด้วย @media (prefers-reduced-motion: reduce) (สไลด์นี้ก็ทำ)
อ่านต่อ: CSS Animations (MDN)

ใช้ AI ช่วยทำแอนิเมชัน (ต้องตรวจเองทุกครั้ง)

จากคำสั่ง (Prompt) สู่แอนิเมชันจริง

Prompt ตัวอย่าง

"เขียน CSS ให้การ์ดสินค้าค่อย ๆ เลื่อนขึ้นและจางเข้ามาทีละใบเมื่อโหลดหน้า ใช้เวลาใบละ 0.4 วินาที เว้นช่วงใบละ 0.1 วินาที และปิดแอนิเมชันเมื่อผู้ใช้ตั้งค่า prefers-reduced-motion"

.card { animation: up .4s ease both; } .card:nth-child(2) { animation-delay: .1s; } .card:nth-child(3) { animation-delay: .2s; } @keyframes up { from { opacity:0; translate:0 24px; } } @media (prefers-reduced-motion: reduce) { .card { animation: none; } }
