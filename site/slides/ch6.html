6.8.1 การประกาศตัวแปรด้วย let และ const (ECMA International, 2023)

ทายก่อน แล้วรันพิสูจน์

const vat = 0.07; vat = 0.1; console.log(vat);

if (true) { let x = 5; } console.log(x);

ใช้แบบไหนดี

  • const ค่าไม่เปลี่ยน (ใช้เป็นค่าเริ่มต้น)
  • let ค่าเปลี่ยนได้ ใช้ได้เฉพาะใน { } ที่ประกาศ
  • var แบบเก่า ขอบเขตกว้างเกิน เลี่ยงได้ควรเลี่ยง

6.8.4 สลับโหมดด้วย classList.toggle และคำนวณราคาพร้อมภาษีแบบเรียลไทม์

ตัวอย่างจากเล่ม ลองใช้จริง

คำนวณราคาสินค้า

const qty = document.querySelector("#qty"); const unit = document.querySelector("#unit"); const out = document.querySelector("#out"); const VAT = 0.07; const calc = () => { const sub = Number(qty.value) * Number(unit.value); const total = sub * (1 + VAT); out.textContent = `ก่อน VAT ${sub.toFixed(2)} รวม ${total.toFixed(2)} บาท`; }; qty.addEventListener("input", calc); unit.addEventListener("input", calc); document.querySelector("#dark") .addEventListener("click", () => document.body.classList.toggle("theme-dark"));

6.9 การเขียนโปรแกรมแบบอะซิงโครนัส

ทายลำดับ: บรรทัดไหนพิมพ์ก่อน?

console.log("A เริ่ม"); setTimeout(() => console.log("B timeout 0 ms"), 0); Promise.resolve().then(() => console.log("C promise")); console.log("D จบ");

คลิกเรียงตามลำดับที่คิดว่าจะแสดง

JavaScript ทำงานทีละบรรทัด (single thread) งานที่ต้องรอ เช่น ตัวจับเวลาหรือการดึงข้อมูลจะถูกพักไว้ แล้วกลับมาทำเมื่องานหลักเสร็จ หน้าเว็บจึงไม่ค้างระหว่างรอ

6.9.2 แนวคิด Promise และความสัมพันธ์กับ async/await

Promise = สัญญาว่าจะได้ผลลัพธ์ในอนาคต

พร้อม

pending → fulfilled หรือ rejected (เปลี่ยนสถานะได้ครั้งเดียว)

then / catch

orderCoffee() .then((cup) => { console.log("ได้", cup); }) .catch((err) => { console.log("ผิดพลาด", err); }) .finally(() => { console.log("จบรายการ"); });

async / await (ผลเหมือนกัน)

async function run() { try { const cup = await orderCoffee(); console.log("ได้", cup); } catch (err) { console.log("ผิดพลาด", err); } finally { console.log("จบรายการ"); } }

6.9.1 ดึงข้อมูลจาก JSONPlaceholder API มาแสดงในตาราง

fetch + async/await ของจริง

async function loadUsers() { out.textContent = "กำลังโหลด..."; try { const res = await fetch( "https://jsonplaceholder.typicode.com/users"); if (!res.ok) throw new Error(res.status); const users = await res.json(); users.forEach((u) => { const tr = document.createElement("tr"); tr.innerHTML = `<td>${u.id}</td>...`; tbody.append(tr); }); } catch (err) { out.textContent = "โหลดไม่สำเร็จ: " + err.message; } }

JSONPlaceholder เป็น API ทดลองที่ให้ข้อมูลสมมติ ต้องต่ออินเทอร์เน็ต

idชื่ออีเมลเมือง

6.10.2 ใช้ Console ค้นหาข้อผิดพลาด (Console Debugging)

ภารกิจ: รันแล้วอ่าน Error แก้ให้ผ่าน

Console

มี 3 จุดผิด: ตัวแปรสะกดผิด ชื่อออบเจกต์ผิด และลูปเกินขอบเขตอาร์เรย์ (ทำให้ได้ NaN)

6.10.3 ความมั่นคงปลอดภัย (OWASP, 2023a)

อย่าเอาข้อความจากผู้ใช้ใส่ innerHTML ตรง ๆ

  • ข้อความที่มีแท็กถูกตีความเป็น HTML และรันสคริปต์ได้ (XSS)
  • ใช้ textContent หรือสร้างเอลิเมนต์ทีละตัว
  • โค้ดจาก AI ชอบใช้ innerHTML ต้องตรวจทุกครั้ง

หน้าเว็บจำลองแยกในกรอบปิด (sandbox) ไม่กระทบหน้านี้

6.10 AI-Assisted JS Development (Haverbeke, 2024; OWASP, 2023a)

ให้ AI ช่วยหาสาเหตุ แต่ตัดสินใจเอง

บทบาท: ผู้ตรวจสอบความปลอดภัย JavaScript งาน: ตรวจโค้ดด้านล่าง 2 ประเด็น 1) Asynchronous: มีจุดลืม await, ไม่จัดการ error หรือ res.ok หรือไม่ 2) XSS: มีการนำข้อมูลภายนอกใส่ innerHTML, eval หรือ document.write หรือไม่ ผลลัพธ์: ตาราง บรรทัด / ปัญหา / ความเสี่ยง / วิธีแก้ [วางโค้ด ไม่วาง API key หรือข้อมูลผู้ใช้จริง]

ตัวอย่างกรอบคำสั่งจากหัวข้อ 6.10.4

ข้อควรระวัง (6.10.3)

  • ห้ามวาง API key รหัสผ่าน หรือข้อมูลส่วนบุคคลใน Prompt
  • ห้ามเก็บรหัสลับไว้ในโค้ด JavaScript ฝั่งผู้ใช้
  • ตรวจ innerHTML, eval, ไลบรารีที่ AI แนะนำ
  • ทดสอบด้วย Console และกรณีข้อมูลผิดพลาด
