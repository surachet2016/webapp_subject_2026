2.8 Front-end และ Back-end

Front-end (หน้าบ้าน)

HTMLCSSJavaScriptBootstrap

เก็บข้อมูลถาวร เช่น สมาชิก สินค้า คำสั่งซื้อ

MySQL/MariaDBPostgreSQLMongoDB

2.5 ฐานข้อมูลเชิงสัมพันธ์ · 2.6 NoSQL

ข้อมูลชุดเดียวกัน เก็บได้สองแบบ

2.6 เปรียบเทียบ

เลือกให้เหมาะกับงาน ไม่มีแบบไหนดีที่สุด

RDBMS (SQL)

  • โครงสร้างตายตัว (Schema) ข้อมูลสม่ำเสมอ
  • ความสัมพันธ์ระหว่างตาราง JOIN ได้
  • ธุรกรรมแบบ ACID เหมาะกับการเงิน ทะเบียน

NoSQL

  • โครงสร้างยืดหยุ่น เพิ่มฟิลด์ได้ง่าย
  • ขยายระบบแนวนอน รองรับข้อมูลมาก
  • 4 แบบ: Key-Value, Document, Column, Graph

ในรายวิชานี้ใช้ MySQL (บทที่ 8) เพราะเหมาะกับระบบที่มีความสัมพันธ์ชัดเจน เช่น นักศึกษา–รายวิชา–ผลการเรียน

mongodb.com · mysql.com

อ่านต่อ: HTTP response status codes (MDN)

2.8.1 HTTPS

HTTPS = HTTP ที่เดินทางผ่านช่องทางเข้ารหัส (TLS)

  • เข้ารหัส คนกลางดักอ่านไม่ได้
  • ตรวจความถูกต้อง ข้อมูลไม่ถูกแก้ระหว่างทาง
  • ยืนยันตัวตน ด้วยใบรับรองจาก CA
  • พอร์ต HTTP 80 · HTTPS 443

ใบรับรองฟรีแบบอัตโนมัติ: Let's Encrypt (ใช้จริงในบทที่ 10)

2.21 เครื่องมือช่วยเขียนโปรแกรมอัจฉริยะ (GitHub, 2024; Google Cloud, 2024)

AI Pair Programming: ให้ AI ช่วย แต่เราเป็นคนขับ

Context: ระบบลงทะเบียนนักศึกษา ใช้ PHP 8 + MySQL Task: เขียนฟังก์ชันตรวจรูปแบบรหัสนักศึกษา 10 หลัก Constraints: ใช้ prepared statement, ไม่ใช้ไลบรารีภายนอก Output: โค้ดพร้อมคอมเมนต์ และกรณีทดสอบ 3 กรณี

ตัวอย่าง Prompt แบบระบุบริบท งาน ข้อจำกัด และรูปแบบผลลัพธ์

ก่อนใช้โค้ดจาก AI

  • อ่านและอธิบายโค้ดได้ทุกบรรทัด
  • ทดสอบด้วยข้อมูลหลายกรณี
  • ตรวจความปลอดภัย (SQL Injection, XSS)
  • ห้ามวางรหัสผ่านหรือข้อมูลส่วนบุคคลจริง
  • บันทึกการใช้ AI แนบงาน
GitHub Copilotผู้ช่วยเขียนโค้ดใน VS Code Gemini Code Assistผู้ช่วยเขียนโค้ดของ Google

  • Git/GitHub เก็บประวัติงาน AI ช่วยได้แต่ต้องตรวจ
  • เก็บข้อมูลผู้ใช้ต้องทำตาม PDPA
