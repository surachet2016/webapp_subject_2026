บทนำ

ระบบจัดการฐานข้อมูล (Database Management System: DBMS) เป็นหัวใจสำคัญของเว็บแอปพลิเคชันเชิงพาณิชย์และระบบสารสนเทศ ที่ต้องการจัดเก็บและประมวลผลข้อมูลปริมาณมากอย่างมีเสถียรภาพ การเชื่อมต่อระหว่างภาษา PHP และฐานข้อมูลเชิงสัมพันธ์ MySQL ในปัจจุบันใช้ส่วนขยาย MySQLi (MySQL Improved) ซึ่งได้รับการพัฒนาเพื่อเพิ่มประสิทธิภาพ รองรับการเขียนโปรแกรมเชิงวัตถุ (OOP) และสนับสนุนการป้องกันช่องโหว่ความปลอดภัยระดับสูงสุดผ่านกลไก Prepared Statements ในบทนี้นักศึกษาจะได้ศึกษาตั้งแต่การออกแบบ และจัดการฐานข้อมูลผ่าน phpMyAdmin, การเชื่อมต่อฐานข้อมูล, การพัฒนาระบบจัดการข้อมูลครบวงจร (CRUD: Create, Read, Update, Delete), การค้นหาและแบ่งหน้าแสดงผล (Pagination), การอัปโหลดไฟล์, ระบบยืนยันตัวตน, การป้องกันภัยคุกคาม SQL Injection, การควบคุมทรานแซกชัน (Transactions) ตลอดจนการประยุกต์ใช้ปัญญาประดิษฐ์ (AI) ในการช่วยออกแบบและตรวจสอบคิวรีฐานข้อมูลอย่างถูกต้องตามหลักวิศวกรรมซอฟต์แวร์

8.1 การสร้างฐานข้อมูล MySQLi ด้วยโปรแกรม PhpMyAdmin (ชาญชัย ศุภอรรถกร, 2564; ชวลิต มนต์เทวัญ, 2565)

PHP MySQL Configuration & Connect to Database (mysqli) สำหรับ mysqli ไม่ใช่ function ใหม่ เริ่มมีมาตั้งแต่รุ่น PHP 5.0 เป็นต้นไป เป็น function ที่ถูกออกแบบไว้ติดต่อกับ Database ของ MySQL โดยเฉพาะ ซึ่งจะมาทำหน้าที่ทดแทน function เดิมอย่าง mysql เหตุผลหลักก็คือ function ของ mysql ธรรมดาถูกประกาศเลิกใช้ (deprecated) ใน PHP 5.5 และถูกถอดออกถาวรตั้งแต่ PHP 7.0 มันค่อนข้างจะโบราณ และมีช่องโหว์เยอะ (หมายถึง เมื่อเขียนแล้วผู้ใช้มักจะทำช่องโหว์ไว้) ฉะนั้น mysqli ซึ่งเป็น function ปัจจุบันที่กำลังถูกแทนที่ mysql มันได้ถูกออกแบบให้ทำงานได้ดีกว่าเดิม ทำงานได้เร็ว และที่สำคัญ มันปลอดภัยกกว่าการใช้ในรูปแบบเดิม ๆ มาก เช่น รองรับแนวคิด OOP ขึ้น การเขียนในรูปแบบของ Parameters Query และ Prepared Statement ที่จะผิดช่องโหว์ของการเกิดข้อผิดพลาดในการ Query ที่เกิดจากการรับค่าในรูปแบบต่าง ๆ รวมทั้งป้องกันการ Hack ผ่านพวก SQL Injection ได้เป็นอย่างดี
สำหรับ mysqli สามารถใช้ได้ตั้งแต่ PHP 5.0เป็นต้นไป ซึ่งในมาตรฐาน PHP 7 และ PHP 8.x ในปัจจุบัน ส่วนขยาย mysql เดิมได้ถูกยกเลิก (Removed) ไปอย่างถาวรแล้ว และกำหนดให้ใช้ส่วนขยาย mysqli หรือ PDO เป็นมาตรฐานหลัก และ PHP Version ใหม่ ๆ ก็เปิด mysqli ให้ทันที หรือในการติดตั้งเองจำเป็นจะต้องเปิดใช้งาน php_mysqli.dll ซึ่งเป็น extension จะต้องหาไฟล์ php_mysqli.dll ที่ตรงกับ Version ของ PHP ที่เรียกใช้ด้วย

8.1.1 การกำหนดความสัมพันธ์ระหว่างตารางด้วย Foreign Key

Foreign Key (คีย์นอก) คือคอลัมน์ในตารางหนึ่งที่อ้างอิงคีย์หลัก (Primary Key) ของอีกตารางหนึ่ง เพื่อรักษาความถูกต้องของความสัมพันธ์ เช่น คำสั่งซื้อต้องอ้างถึงลูกค้าที่มีอยู่จริง ข้อกำหนดคือคอลัมน์ทั้งสองต้องมีชนิดข้อมูลตรงกัน และตารางต้องใช้เอนจิน InnoDB (ตัวอย่างต่อไปนี้ใช้ตาราง customer ที่สร้างไว้ในหัวข้อ 8.1)

`OrderID` int NOT NULL AUTO_INCREMENT,

ON DELETE RESTRICT ON UPDATE CASCADE

ทดสอบความสัมพันธ์ด้วยคำสั่งต่อไปนี้ MySQL จะปฏิเสธคำสั่งที่ทำให้ข้อมูลไม่สัมพันธ์กัน (รหัสข้อผิดพลาด 1452 เมื่อเพิ่มข้อมูลที่อ้างถึงลูกค้าที่ไม่มี และ 1451 เมื่อลบลูกค้าที่ยังมีคำสั่งซื้ออ้างอิง) เพราะกำหนด ON DELETE RESTRICT ไว้

8.2 การเชื่อมต่อฐานข้อมูล mysqli ด้วยคำสั่ง mysqli_connect

การเขียนภาษา PHP เชื่อมต่อฐานข้อมูล mysqli ด้วยคำสั่ง mysqli_connect โดยตัวอย่างจะทำการเชื่อมต่อกับฐานข้อมูลชื่อ db_test ของ MySQL และใช้คำสั่ง mysqli_connect_errno เช็คสถานะการเชื่อมต่อ สามารถเขียนโปรแกรมได้ดังนี้

ข้อควรระวังเรื่องรหัสผ่านของฐานข้อมูล: ตัวอย่างในบทนี้เชื่อมต่อด้วยผู้ใช้ root และรหัสผ่านว่าง ("") ซึ่งเป็นค่าเริ่มต้นของ XAMPP บน Windows ถ้าใช้ MAMP บน macOS รหัสผ่านของ root คือ root ให้แก้ค่าที่ 3 ของ mysqli_connect() (หรือตัวแปร $userPassword) เป็น "root" ในทุกตัวอย่างของบทนี้ และถ้าระบุ host เป็น 127.0.0.1 ต้องใส่พอร์ต 8889 ด้วย (localhost ไม่ต้องระบุพอร์ต) รายละเอียดดูภาคผนวก ค ข้อ ค.3 เมื่อนำขึ้นเซิร์ฟเวอร์ของรายวิชา ต้องใช้ผู้ใช้ รหัสผ่าน และชื่อฐานข้อมูลที่ผู้สอนแจ้งแทน root (ภาคผนวก จ) ในงานจริงไม่ควรใช้ root และไม่ควรเก็บรหัสผ่านไว้ในโค้ดตรง ๆ ให้สร้างผู้ใช้เฉพาะโครงการและเก็บค่าตั้งไว้ในไฟล์แยก

โค้ด
<?php
    $c = mysqli_connect("localhost", "root", "", "db_test");
    if (mysqli_connect_errno()) {
        echo "ไม่สามารถเชื่อมต่อฐานข้อมูลได้ เพราะ " . mysqli_connect_error();
        exit();
    } else {
        echo "เชื่อมต่อฐานข้อมูลเรียบร้อย";
        mysqli_close($c);
    }

?>

8.12 การป้องกันช่องโหว่ SQL Injection ด้วย Prepared Statements (Open Web Application Security Project [OWASP], 2023; The PHP Group, 2024)

SQL Injection เป็นหนึ่งในภัยคุกคามความปลอดภัยทางเว็บที่อันตรายที่สุด (OWASP Top 10) เกิดจากการที่นักพัฒนานำค่าตัวแปรจากผู้ใช้ (เช่น $_POST หรือ $_GET) ไปเชื่อมต่อกับสตริงคำสั่ง SQL โดยตรง ทำให้ผู้ไม่ประสงค์ดีสามารถแทรกคำสั่งอันตราย เช่น ' OR '1'='1 เพื่อเข้าสู่ระบบโดยไม่ต้องทราบรหัสผ่าน หรือขโมยข้อมูลทั้งฐานข้อมูลได้

8.12.1 การทำงานและไวยากรณ์ของ Prepared Statements ใน MySQLi

Prepared Statements แก้ปัญหานี้โดยการแยก "โครงสร้างคำสั่ง SQL" ออกจาก "ข้อมูลนำเข้า (Data Parameters)" โดยส่งคำสั่งไปคอมไพล์บนเซิร์ฟเวอร์ฐานข้อมูลก่อน แล้วจึงส่งค่าข้อมูลไปผูก (Bind) ในภายหลัง ข้อมูลจึงไม่มีทางถูกตีความเป็นคำสั่ง SQL ได้:

// ตัวอย่างการเขียน Prepared Statement สำหรับตรวจสอบการล็อกอินอย่างปลอดภัย
$stmt = $conn->prepare("SELECT id, username, password_hash FROM users WHERE email = ? AND status = ?");
$status = 'active';
$stmt->bind_param("ss", $email, $status); // "ss" หมายถึงสตริง 2 ตัว (s=string, i=integer, d=double, b=blob)
$stmt->execute();
$result = $stmt->get_result();
if ($row = $result->fetch_assoc()) {
if (password_verify($password, $row['password_hash'])) {
// ล็อกอินสำเร็จ
}
}
$stmt->close();

8.13 การจัดการทรานแซกชันเพื่อความสมบูรณ์ของข้อมูล (Silberschatz, Korth, & Sudarshan, 2024; MySQL AB & Oracle, 2024) (Database Transactions & Rollback)

ในระบบงานธุรกิจที่มีการปรับปรุงข้อมูลหลายตารางพร้อมกัน เช่น ระบบสั่งซื้อสินค้า (ต้องบันทึกใบสั่งซื้อ, บันทึกรายการสินค้า, และตัดสต็อกสินค้า) หากเกิดข้อผิดพลาดระหว่างขั้นตอน ข้อมูลจะเกิดความไม่สอดคล้องกัน (Inconsistency) MySQLi จึงรองรับคุณสมบัติ Transactions ตามหลักการ ACID โดยทำงานร่วมกับเอนจิน InnoDB ดังนี้:

$conn->begin_transaction(); // เริ่มต้นทรานแซกชัน
try {
$conn->query("INSERT INTO orders (user_id, total) VALUES (1, 500)");
$orderId = $conn->insert_id;
$conn->query("INSERT INTO order_items (order_id, product_id, qty) VALUES ($orderId, 10, 2)");
$conn->query("UPDATE products SET stock = stock - 2 WHERE id = 10");

$conn->commit(); // ยืนยันการบันทึกทั้งหมดเมื่อทุกคำสั่งทำงานถูกต้อง
echo "การสั่งซื้อเสร็จสมบูรณ์";
} catch (Exception $e) {
$conn->rollback(); // ยกเลิกการเปลี่ยนแปลงทั้งหมด ย้อนกลับสู่สถานะเดิม
echo "เกิดข้อผิดพลาด ยกเลิกรายการ: " . $e->getMessage();
}

8.14 การเขียน MySQLi เชิงวัตถุ (OOP) และตัวอย่างโค้ดมาตรฐาน (ชาญชัย ศุภอรรถกร, 2564; ชวลิต มนต์เทวัญ, 2565)

• การตั้งค่ารหัสอักขระ utf8mb4: ต้องเรียกใช้ $mysqli->set_charset("utf8mb4") ทุกครั้ง เพื่อรองรับภาษาไทยครบถ้วนและอีโมจิโดยไม่เกิดปัญหาเครื่องหมายคำถาม (?)

8.14.1 ตัวอย่างโค้ด MySQLi OOP: Prepared Statements และ Database Transactions

<?php
// เชื่อมต่อฐานข้อมูลแบบ Object-Oriented
$mysqli = new mysqli("localhost", "db_user", "db_pass", "course_db");
if ($mysqli->connect_errno) {
die("การเชื่อมต่อฐานข้อมูลล้มเหลว: " . $mysqli->connect_error);
}
$mysqli->set_charset("utf8mb4"); // รองรับภาษาไทย 100%

// เริ่มต้นระบบธุรกรรม (Database Transaction)
$mysqli->begin_transaction();

try {
// 1. เพิ่มข้อมูลการลงทะเบียน (Prepared Statements)
$stmt1 = $mysqli->prepare("INSERT INTO enrollments (student_id, course_code, registered_at) VALUES (?, ?, NOW())");
$studentId = 101;
$courseCode = '07-034-210';
$stmt1->bind_param("is", $studentId, $courseCode);
$stmt1->execute();
$stmt1->close();

// 2. ปรับลดที่นั่งว่างในรายวิชา
$stmt2 = $mysqli->prepare("UPDATE courses SET available_seats = available_seats - 1 WHERE course_code = ? AND available_seats > 0");
$stmt2->bind_param("s", $courseCode);
$stmt2->execute();

if ($stmt2->affected_rows === 0) {
throw new Exception("ที่นั่งในรายวิชาเต็มแล้ว ไม่สามารถลงทะเบียนได้");
}
$stmt2->close();

// ยืนยันการทำงานของทั้งสองคำสั่ง (Commit)
$mysqli->commit();
echo "ลงทะเบียนเรียนสำเร็จ";
} catch (Exception $e) {
// ยกเลิกการทำงานทั้งหมดหากมีข้อผิดพลาด (Rollback)
$mysqli->rollback();
echo "เกิดข้อผิดพลาดในการลงทะเบียน: " . $e->getMessage();
}
$mysqli->close();
?>

3. ภัยคุกคามแบบ SQL Injection มีรูปแบบและหลักการโจมตีอย่างไร และเหตุใดการใช้ Prepared Statements (ร่วมกับ prepare() และ bind_param()) จึงสามารถป้องกันการโจมตีนี้ได้อย่างสมบูรณ์

4. ในระบบการทำธุรกรรม (Transactions) บนฐานข้อมูล จงอธิบายความสำคัญของคุณสมบัติ ACID และยกตัวอย่างสถานการณ์ที่จำเป็นต้องใช้คำสั่ง rollback() เพื่อรักษาความสมบูรณ์ของข้อมูล

5. จงอธิบายหลักการทำงานของการแบ่งหน้าแสดงผลข้อมูล (Pagination) ในภาษา PHP+MySQLi โดยระบุบทบาทของคำสั่ง LIMIT และ OFFSET ใน SQL

6. จงอธิบายว่าเครื่องมือผู้ช่วย AI (AI Coding Assistants) สามารถช่วยเหลือนักพัฒนาในการออกแบบ Schema ฐานข้อมูลและการปรับแต่งประสิทธิภาพคำสั่ง SQL (Query Optimization) ได้อย่างไรบ้าง
