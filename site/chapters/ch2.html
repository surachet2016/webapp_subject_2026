เนื้อหา

2.1 แนะนำภาษา HTML (บัญชา ปะสีละเตสัง, 2565ข)

HTML (เอชทีเอ็มแอล - ย่อมาจากคำว่า Hypertext Markup Language) ในการสร้างเว็บไซต์นั้น ภาษาหลักที่ใช้งานการเขียนส่วนใหญ่จะเป็น ซึ่งเป็นภาษามาตรฐาน ถูกใช้กันมานาน และเป็นที่แพร่หลายในหมู่คนที่ทำเว็บไซต์ โดยภาษา ถูกกำหนดมาตรฐาน โดยองค์กร W3C (The World Wide Web Consortium) HTML เป็น ภาษามาร์กอัป ปัจจุบันที่ใช้ในการสร้างเว็บเพจ หรือข้อมูลอื่นที่เรียกดูผ่านทาง เว็บเบราว์เซอร์ ซึ่งตัวโค้ดจะแสดงโครงสร้างของข้อมูล ในการแสดง หัวข้อ ลิงก์ ย่อหน้า รายการ รวมถึงการสร้างแบบฟอร์ม เชื่อมโยงภาพหรือวิดีโอด้วย

เริ่มพัฒนาโดย ทิม เบอร์เนอรส์ ลี (Tim Berners Lee) ในปัจจุบัน เป็นมาตรฐานหนึ่งของ ISO ซึ่งจัดการโดย World Wide Web Consortium (W3C) ในปัจจุบัน ทาง W3C ผลักดัน รูปแบบของ แบบใหม่ ที่เรียกว่า X 1.0 ซึ่งเป็นลักษณะของโครงสร้าง XML ที่มีหลักเกณฑ์ในการกำหนดโครงสร้างที่มาตรฐานกว่า มาใช้ทดแทน รุ่น 4.01 ที่ใช้กันอยู่ในปัจจุบัน ขณะที่ 5 ยังคงยังอยู่ในระหว่างการพัฒนา

HTML5 (เอชทีเอ็มแอลไฟล์) เป็น ภาษามาร์กอัป สำหรับ เวิลด์ไวด์เว็บ รุ่นต่อไป ของ โดยตัวแรกได้ออกมาเมื่อ 22 มกราคม พ.ศ. 2551 โดย 5 มีรูปแบบสองแบบที่ร่วมกันคือ แบบดั้งเดิม (text/html) และแบบที่สองคือ X

  • HTML5 เป็นมาตรฐานใหม่ของ HTML XHTML
  • HTML5 ออกแบบมาเพื่อลดการใช้ Flash
  • HTML5 เข้ามาแทนที่ภาษา script
  • HTML5 ช่วยให้อุปกรณ์มีความเป็นอิสระต่อกัน
  • รูปแบบการพัฒนาเป็นแบบ open source

สิ่งที่น่าสนใจใน HTML5 คือสามารถทำงานข้ามระบบ (Platform) ได้อย่างไม่มีปัญหา

สามารถใช้งานกับอุปกรณ์อื่นๆ ได้สะดวกขึ้น โดยเฉพาะโทรศัพท์มือถือ หรืออุปกรณ์ที่มีหน้าจอหลายขนาด เช่น แท็บเล็ต(Tablet) สนับสนุนการวาดภาพ การเปิดดู video และ audio เช่น ไฟล์ ogg ใช้ในการควบคุม ตารางนัดหมาย วัน เวลา email url และการ search

HTML5 มีความพิเศษกว่า HTML คือ

  • การเขียน Doctype เขียนได้ง่ายขึ้น (Doctype คือตัวที่บ่งบอกว่าไฟล์ที่เขียนเขียนด้วยเวอร์ชันอะไร) คือไม่ต้องเขียนกำหนดเวอร์ชัน ซึ่งจะสามารถนำไปใช้กับเวอร์ชันใดๆก็ได้ในอนาคต
  • การกำหนดภาษาทำได้ง่ายขึ้น เมื่อก่อนจะต้องเขียน xmln หรือ xml:lang ในแท็ก <html> เพื่อกำหนดภาษาของหน้า แต่สำหรับ HTML5 จะเหลือแค่ : <html lang=”en”>
  • การกำหนดตัวอักษรก็ทำได้ง่ายขึ้นเช่นกัน เมื่อก่อนจะต้องเขียนแท็ก meta ยาว ๆ เพื่อกำหนด Character Set เป็น UTF-8 แต่ตอนนี้เราสามารถกำหนดโดยเขียนแค่นี้: <meta charset=”utf-8″ />
  • ไม่ต้องมี “/” สำหรับแท็กเดี่ยวแล้ว แท็กเดี่ยว หมายถึงแท็กที่ไม่มีแท็กปิด เช่น <img> <input> <br> ซึ่งจะต่างกับแท็กที่เป็นแท็กเปิดปิดอย่าง <div></div> <strong></strong> โดยถ้าเป็นเมื่อก่อน แท็กเดี่ยวจะบังคับให้มี “/” ปิดท้าย เช่น <img /> หรือ <br /> แต่ใน HTML5 นี้แท็กเดี่ยวไม่จำเป็นต้องมี “/” ปิดท้ายแล้ว
  • HTML5 มีความพิเศษกว่า XHTML คือ HTML5 จะมีโครงสร้างที่ง่ายกว่า XHTML

สรุปได้ว่า HTML5 นำคุณลักษณะเด่นของ XHTML และ HTML มารวมกัน เพื่อให้การสร้างเว็บไซต์ทำได้ง่ายและสะดวกยิ่งขึ้น

2.2 เทคโนโลยีฝั่งเซิร์ฟเวอร์ตระกูล Microsoft (ASP.NET Core และวิวัฒนาการจาก ASP)

ASP เป็นเทคโนโลยีประเภท (โปรแกรมที่ทำงานบนเครื่อง Server) ที่นิยมใช้อย่างแพร่หลาย สร้างโดยบริษัท สำหรับระบบปฏิบัติการ ซึ่งใช้ร่วมกับโปรแกรม หรือ IIS. ASP นั้นใช้ภาษาสคริปต์ , หรือ ในการเขียน โดยเว็บเพจที่ใช้ ASP เขียน จะระบุเป็นตระกูลไฟล์ที่ลงท้ายด้วย .asp ซึ่ง ASP ยังสามารถใช้เขียนเพื่อควบคุมฐานข้อมูลต่างๆ ผ่าน และอื่นๆ

ปัจจุบันนี้ไมโครซอฟท์ได้ยกเลิกการพัฒนาเทคโนโลยี ASP แล้วและได้เปลี่ยนเป็น แทน. ซึ่งคำว่า Classic ASP นั้นอาจใช้เรียกแทนเอเอสพีเดิม

ASP (เอเอสพี) เป็นโปรแกรมที่ทำงานบนเครื่อง Server IIS คล้ายๆ กับ php
ASP ย่อมาจาก Active Server Pages คือ โปรแกรมที่ทำงานบนเครื่อง เรียกว่าเป็นการทำงานแบบ Server Side พัฒนาโดยบริษัทไมโครซอฟท์ ประโยชน์ของ ASP ใช้สำหรับสร้างงาน(application)ขั้นสูง ในอินเทอร์เน็ต-อินทราเน็ต ช่วย เสริมการทำงานที่ไฟล์ ธรรมดาทำไม่ได้ หรือต้องการให้งานต่าง ๆเป็นไปอย่างอัตโนมัติโดยผู้ใช้ไม่ต้องทำการปรับปรุงข้อมูลเอง หรือเรียก DHTML (Dynamic HTML) คือ เป็นเว็บเพจที่สามารถเปลี่ยนแปลงลักษณะต่าง ๆ ได้นั้นเอง
หลักการทำงานของ ASP

  • ผู้ใช้ ASP สร้างไฟล์ที่มีนามสกุลเป็น .asp ขึ้นมา
  • นำไฟล์นั้นไปไว้ในเครื่องคอมพิวเตอร์ที่ทำหน้าที่เป็น web server ที่ติดตั้งโปรแกรม ASP ไว้ และเชื่อมต่ออยู่กับเครือข่ายอินเทอร์เน็ต
  • เมื่อมีผู้ใช้รายใดเรียกใช้ไฟล์นั้นผ่านโปรแกรมเบราว์เซอร์(chrome, Mozillafirefox ..) โปรแกรม ASP ใน web server จะเรียกไฟล์นั้นขึ้นมาอ่านแล้วทำตามคำสั่งต่าง ๆที่ผู้สร้างไฟล์นั้นได้กำหนดขึ้น
  • โปรแกรม ASP ใน Web Server ส่งผลที่ได้กลับไปให้ผู้เรียกใช้โดยแสดงผลที่โปรแกรมเบราว์เซอร์ของผู้เรียก

2.3 แนะนำภาษา PHP

PHP ภาษาพีเอชพี ในชื่อภาษาอังกฤษว่า PHP ซึ่งใช้เป็นคำย่อ จากคำว่า PHP Hypertext Preprocessor หรือชื่อเดิม Personal Home Page

พีเอชพี (PHP) คือ ในลักษณะ โดยลิขสิทธิ์อยู่ในลักษณะ ภาษาพีเอชพีใช้สำหรับจัดทำ และแสดงผลออกมาในรูปแบบ โดยมีรากฐานโครงสร้างคำสั่งมาจากภาษา และ ซึ่ง ภาษาพีเอชพี นั้นง่ายต่อการเรียนรู้ ซึ่งเป้าหมายหลักของภาษานี้ คือให้นักพัฒนาเว็บไซต์สามารถเขียน ที่มีการตอบโต้ได้อย่างรวดเร็ว

ข้อสังเกตเพื่อการเรียนรู้: ทำไมรายวิชานี้จึงเน้นภาษา PHP

• PHP ยังเป็นภาษาฝั่งเซิร์ฟเวอร์ที่ใช้มากที่สุด ประมาณร้อยละ 69 ของเว็บไซต์ที่ตรวจพบภาษาฝั่งเซิร์ฟเวอร์ได้ (W3Techs, 2026)

• เป็นรากฐานของระบบจัดการเนื้อหาที่นิยม เช่น WordPress และ Joomla ที่เรียนในบทที่ 9 รวมทั้งเฟรมเวิร์ก Laravel

• เรียนรู้ได้ง่าย ติดตั้งและทดลองเขียนได้ฟรีด้วย XAMPP และเชื่อมต่อกับ MySQL ได้โดยตรง ตามเนื้อหาบทที่ 7 และ 8

• ควรทราบว่าตลาดงานยังใช้ JavaScript/TypeScript (Node.js), Python, Java และ C# อย่างกว้างขวาง หลักการที่เรียนในรายวิชานี้ เช่น โปรโตคอล HTTP การรับส่งข้อมูลฟอร์ม ภาษา SQL และสถาปัตยกรรม MVC นำไปใช้กับภาษาอื่นได้

2.4 แนะนำ CSS

CSS ย่่อมาจาก Cascading style sheet คือภาษาที่ใช้เป็นส่วนของการจัดรูปแบบการแสดงผลเอกสาร เช่น สีอักษร สีพิ้นหลัง ขนาดตัวอักษร จัดการเลย์เอ้าท์ ให้สวยงามและอื่นๆ ปัจจุบันที่ใช้กันคือ css3 ซึ่งโค้ด CSS3 ก็ถูกพัฒนามาจาก CSS แบบธรรมดา สามารถกำหนดทำอะไรได้มากขึ้น สวยงามขึ้น และบางโค้ดอาจสั้นลง เพื่อการจดจำง่าย ไม่ยุ่งยากและซับซ้อนน้อยลง

ใน CSS3 นั้น ระบบการทำงานแต่ละอย่างจะถูกแยกออกมาเป็น Module เดี่ยวๆ ของใครของมัน รวมไปถึง Selectors ของ CSS3 เองด้วย ใน CSS2 Selectors นั้น W3C ได้รวมเอา Selectors เป็นองค์ประกอบหลักของการเขียน CSS ใน ทุกๆ Models (CSS2 เรียก Model ส่วน CSS3 เรียก Module) CSS3 นั้นแยกเนื้อหาออกเป็น Modules ซึ่งในแต่ละ Module นั้นจะมี CSS Properties และ Values เพื่อใช้ในการควบคุมการแสดงผล ของ HTML โดยสื่อสารผ่าน Selectors ซึ่งใน CSS3 ทาง W3C ได้ยกเรื่องของ Selectors ออกมาเป็น CSS Selectors Module Level 3 ซึ่งถือเป็น Module แรกสุดของ CSS3 ที่ประกาศเป็นสถานะ PR (Proposed Recommendation) แต่ในขณะเดียวกัน CSS2.1 ยังอยู่ในสถานะ CR (Candidate Recommendation) อยู่เลย

CSS3 มี Feature ใหม่เพิ่มขึ้นมา ดังนี้

  • Border Radius
  • Border Images
  • Box Shadow
  • Multi-Column Layout
  • Font-face
  • Attribute Selectors
  • Opacity and RGBA

Module หลักๆ ของ css3 มีดังนี้

  • Selectors
  • Box Model
  • Backgrounds and Borders
  • Text Effects
  • 2D/3D Transformations
  • Animations
  • Multiple Column Layout
  • User Interface

2.5 แนะนำฐานข้อมูลเชิงสัมพันธ์และ MySQL (Codd, 1970; ชาญชัย ศุภอรรถกร, 2564)

MySQL คือ ระบบจัดการฐานข้อมูล หรือ Database Management System (DBMS) แบบข้อมูลเชิงสัมพันธ์ หรือ Relational Database Management System (RDBMS) ซึ่งเป็นระบบฐานข้อมูลที่จัดเก็บรวบรวมข้อมูลในรูปแบบตาราง โดยมีการแบ่งข้อมูลออกเป็นแถว (Row) และในแต่ละแถวแบ่งออกเป็นคอลัมน์ (Column) เพื่อเชื่อมโยงระหว่างข้อมูลในตารางกับข้อมูลในคอลัมน์ที่กำหนด แทนการเก็บข้อมูลที่แยกออกจากกัน โดยไม่มีความเชื่อมโยงกัน ซึ่งประกอบด้วยข้อมูล (Attribute) ที่มีความสัมพันธ์เชื่อมโยงกัน (Relation) โดยใช้ RDBMS Tools สำหรับการควบคุมและจัดเก็บฐานข้อมูลที่จำเป็น ทำให้นำไปประยุกต์ใช้งานได้ง่าย ช่วยเพิ่มประสิทธิภาพในการทำงานให้มีความยืดหยุ่นและรวดเร็วได้มากยิ่งขึ้น รวมถึงเชื่อมโยงข้อมูล ที่จัดแบ่งกลุ่มข้อมูลแต่ละประเภทได้ตามต้องการ จึงทำให้ MySQL เป็นโปรแกรมระบบจัดฐานข้อมูลที่ได้รับความนิยมสูง

MySQL เป็น ที่ถูกพัฒนาขึ้นจาก MySQL AB ในประเทศสวีเดน โดยชาวสวีเดน 2 คน คือ David Axmark และ Allan Larsson ร่วมกับชาวฟินแลนด์ Michael Monty Widenius ซึ่งต่อมาในปี ค.ศ. 2008 ถูกซื้อกิจการโดย Sun Microsystems และภายหลัง Oracle Corporation ได้เข้าซื้อกิจการในปี ค.ศ. 2010

MySQL มีหน้าที่จัดเก็บข้อมูลอย่างเป็นระบบ รองรับคำสั่งภาษา Structured Query Language หรือ SQL เพื่อจัดการกับฐานข้อมูลโดยเฉพาะ เป็นภาษามาตรฐานบนระบบฐานข้อมูลเชิงสัมพันธ์และเป็นระบบเปิด (Open System) ที่มีโครงสร้างของภาษาที่เข้าใจง่าย ไม่ซับซ้อน และนิยมใช้งานร่วมกับภาษาโปรแกรม รวมถึงภาษาอื่น ๆ ที่สามารถทำงานร่วมกันกับฐานข้อมูล MySQL ได้หลากหลาย เช่น C, C++, Python, Java เป็นต้น อีกทั้ง MySQL ยังได้รับการออกแบบและปรับให้มีความเหมาะสมสำหรับการพัฒนา Website และ Web Application ทำให้สามารถรองรับการทำงานได้ทุกแพลตฟอร์ม รวมถึงการอนุญาตให้ผู้ใช้งานหลายคนสามารถใช้งานพร้อมกันได้ (Multi-user) นอกจากนั้นยังสามารถจัดการและสร้างฐานข้อมูลจำนวนมากรวมถึงประมวลผลหลาย ๆ งานได้พร้อมกัน (Multi-threaded) อย่างสมบูรณ์ จึงทำให้ MySQL เป็นตัวเลือกยอดนิยมสำหรับธุรกิจการพาณิชย์อิเล็กทรอนิกส์ หรือ Electronic Commerce (E-Commerce) และเหมาะสำหรับการนำไปใช้งานสร้างเว็บไซต์ทั่วไป เพราะมีความแม่นยำ ครบครัน ช่วยให้เข้าถึงข้อมูลได้อย่างรวดเร็ว อีกทั้งยังมีความน่าเชื่อถือสูง และยังมีโปรแกรมเสริมช่วยจัดฐานข้อมูลที่ใช้งานง่าย เช่น MySQL Admin, เป็นต้น

MySQLi (มายเอสคิวเอลไอ) มีคุณสมบัติอะไรบ้าง MySQLi คือ การขยายออกมาจากฐานข้อมูล MySQLi ย่อมาจาก MySQL Improve (มายเอสคิวเอล อิมพรูว) และ MySQLi คือ MySQL เวอร์ชันใหม่ที่มีคุณสมบัติต่าง ๆ มากขึ้น และมีประสิทธิภาพมากกว่า ซึ่งเป็นการพัฒนามาจาก MySQL ที่เราใช้กันอยู่ เพื่อให้รองรับ หรือเรียกใช้พวก ที่มีเพิ่มขึ้นของ ขึ้นไป

คุณสมบัติของ MySQLi

  • เป็นแบบ object-oriented หรือที่เรีกกันว่า oop
  • รองรับคำสั่ง prepared (ป้องกัน SQL Injection)
  • รองรับคำสั่ง transactions
  • รองรับหลายคำสั่งพร้อมกัน (multiple statements)
  • เพิ่มเติมการรองรับบน Server ต่าง ๆ
  • เพิ่มเติมการรองรับ debugging

2.6 แนะนำฐานข้อมูล NoSQL (Not Only SQL) (จีราวุธ วารินทร์, 2566; ชาญชัย ศุภอรรถกร, 2564)

Non-SQL ย่อมาจาก Non-relational database บางท่านอาจจะเรียกว่า Not only SQL ก็ไม่ได้ผิดแต่อย่างใด เป็น Database อื่น ๆ ที่ไม่ได้เป็นแบบ Relational หรือมีความสัมพันธ์กันชัดเจนแบบ Pattern เหมาะสำหรับการใช้งานจำพวก Big Data และ Real-time Web Application

กล่าวโดยสรุป NoSQL เกิดขึ้นเพื่อแก้ปัญหาข้อจำกัดของ RDBMS แต่ก็มีข้อจำกัดบางประการเช่นกัน ซึ่งจะเปรียบเทียบข้อดีและข้อเสียไว้ในตอนท้ายของหัวข้อนี้ สำหรับประเภทของ NoSQL แบ่งออกเป็น 4 แบบหลัก ได้แก่

  • Document -> ข้อมูลและ Metadata จะเก็บเป็นลำดับชั้นในรูปแบบ Semi-structure data เช่น JSON หรือ XML ใน Database ตัวอย่าง Database Software ที่ใช้งานลักษณะนี้ ได้แก่ Cosmos DB, IBM Domino, MongoDB, Couchbase, ArangoDB
  • Key-Value -> เป็นการเก็บ Record ที่ไม่มีอะไรซับซ้อน มีแค่ Key และ Value ทำให้สามารถเข้าถึงข้อมูลได้รวดเร็ว โดยการเข้าถึงข้อมูลก็ให้ใช้ Key ก็จะได้ Value ที่ต้องการ ตัวอย่าง Database Software ที่ใช้งานลักษณะนี้ ได้แก่ Redis, Memcached, Apache Ignite, Couchbase, Dynamo
  • Wide-Column -> รูปแบบของ Wide-Column จะบันทึกข้อมูลในรูปแบบ Tables (Rows และ Columns) แต่จะต่างจาก RDBMS ตรงที่ แต่ละ Rows จะไม่ Fix Column (ถ้าเป็น RDBMS จะ Fix มาเป็น Pattern เดียวกัน) ตัวอย่าง Database Software ที่ใช้งานลักษณะนี้ ได้แก่ Amazon DynamoDB, Cassandra, Azure Tables, Accumulo, HBase
  • Graph -> ข้อมูลจะเก็บอยู่ในรูปแบบกราฟแผนภูมิ มี Node และ Edge ที่เชื่อมต่อกัน ทำให้ไม่ต้องนำข้อมูลมา JOINS กันเหมือนของ RDBMS ตัวอย่าง Database Software ที่ใช้งานลักษณะนี้ ได้แก่ ArangoDB, InfiniteGraph, Apache Giraph, MarkLogic, Neo4J, OrientDB, Virtuoso
  • แบบ RDBMS (สีฟ้า) จะเห็นได้ว่า Columns เป็นค่าเดิมตลอด
  • แบบ NoSQL Wide-Column (สีเขียวและสีขาว) สังเกตได้ว่าในแต่ละ Row จะใส่ Column อะไรลงไปก็ได้ ไม่ต้องมี Constraints เหมือน RDBMS

จากแต่ละประเภทที่ได้อธิบาย จะเห็นได้ว่าลักษณะของ Database แบบ NoSQL จะไม่ได้เคร่งในเรื่องของความเป็นระเบียบของข้อมูล สามารถกระจายอยู่ที่ไหนก็ได้ ทำให้หาก Database มีขนาดที่ใหญ่มากขึ้น การ Scale Server จะเป็นการเพิ่มในแนวราบมากกว่า (Horizontal) ก็คือแทนที่จะเพิ่ม Spec Resource เหมือนกับแบบ RDBMS จะเป็น Scale โดยการเพิ่ม Server ไปเลยมากกว่า

สรุปความแตกต่างระหว่างระบบจัดการฐานข้อมูลเชิงสัมพันธ์ (RDBMS) กับฐานข้อมูลแบบ NoSQL มีดังนี้

ข้อดีและข้อเสียของ SQL และ NoSQL

สำหรับข้อดีและข้อเสียของ SQL และ NoSQL ควรพิจารณาเลือกใช้ให้เหมาะสมกับลักษณะข้อมูลและความต้องการของระบบ ดังรายละเอียดต่อไปนี้

ฐานข้อมูล NoSQL เหมาะสำหรับแอปพลิเคชันสมัยใหม่ เช่น อุปกรณ์เคลื่อนที่ เว็บ และเกมที่จำเป็นต้องมีฐานข้อมูลที่ยืดหยุ่น ปรับขนาดได้ ประสิทธิภาพสูง และทำงานได้ดีเยี่ยมเพื่อมอบประสบการณ์ผู้ใช้ที่ยอดเยี่ยม

  • ความยืดหยุ่น: โดยทั่วไป ฐานข้อมูล NoSQL จะมีแบบแผนยืดหยุ่นที่ทำให้การพัฒนาเกิดขึ้นเร็วและทำซ้ำคำสั่งได้ดียิ่งขึ้นกว่าเดิม โมเดลข้อมูลที่ยืดหยุ่นทำให้ฐานข้อมูล NoSQL เหมาะสมที่สุดสำหรับข้อมูลแบบกึ่งมีโครงสร้างและไม่มีโครงสร้าง
  • ความสามารถในการปรับขนาด: โดยทั่วไป ฐานข้อมูล NoSQL มักถูกออกแบบมาให้ปรับขนาดออกได้โดยใช้คลัสเตอร์แบบกระจายของฮาร์ดแวร์แทนการปรับขนาดขึ้นโดยเพิ่มเซิร์ฟเวอร์ที่มีราคาแพงและมีประสิทธิภาพสูง ผู้ให้บริการระบบคลาวด์บางเจ้าจัดการปฏิบัติการนี้อยู่เบื้องหลังในแบบบริการที่มีการจัดการเต็มรูปแบบ
  • ประสิทธิภาพสูง: ฐานข้อมูล NoSQL ได้รับการปรับปรุงประสิทธิภาพสำหรับโมเดลข้อมูลบางโมเดล และเข้าถึงรูปแบบที่เปิดใช้งานประสิทธิภาพที่สูงกว่าการพยายามดำเนินการทำงานที่คล้ายกันด้วยฐานข้อมูลเชิงสัมพันธ์
  • ทำงานได้ดีเยี่ยม: ฐานข้อมูล NoSQL มี API การทำงานและประเภทข้อมูลที่สร้างตามวัตถุประสงค์สำหรับโมเดลข้อมูลแต่ละโมเดลที่สอดคล้องกัน

2.7 แนะนำเว็บเบราว์เซอร์ (Web Browser)

เป็นซอฟต์แวร์ที่ใช้สำหรับแปลงโค้ด HTML เรียกว่า เว็บเบราว์เซอร์ (Web Browser) ได้แก่ Internet Explorer, Microsoft Edge, Firefox, Safari, Google Chrome และ Opera เป็นต้น

2.8 แนะนำ Front-end และ Back-end

Front-end และ Back-end เป็นส่วนหนึ่งของระบบ หรือ ระบบจัดการเนื้อหาของเว็บไซต์

front-end หมายถึง โปรแกรมหนึ่งโปรแกรมใด หรือคอมพิวเตอร์เครื่องหนึ่งเครื่องใดที่ซ่อนรายละเอียดของการเข้าถึงข้อมูลเอาไว้ สรุปง่าย ๆ ได้ว่า ตัวโปรแกรมนั้นเองที่มีตัวเสริมหน้า เป็นตัวกันมิให้ใครเข้าถึงข้อมูลได้ นอกจากจะรู้จักคำสั่งต่าง ๆ จะเรียกกันสั้นๆว่า หน้าบ้าน หรือเป็นส่วนติดต่อผู้ใช้ (User interface) ไม่ว่าจะเป็น หน้าโฮม หน้าเว็บเพจ เนื้อหาต่าง ๆ รูปภาพ ลิงก์ เป็นต้น เป็นส่วนที่ user ทั่วไปสามารถเห็นและเข้ามาใช้งานได้ของเว็บไซต์ ส่วนนี้จะแสดงหน้าตาของเว็บไซต์ให้ผู้เข้าชมเห็น การออกแบบก็เป็นส่วนที่ช่วยดึงดูดและทำให้ผู้อื่นสนใจเว็บไซต์ ทั้งความสวยงาม การใช้งานเว็บไซต์ที่เข้าใจง่าย สะดวก และทำให้ผู้เข้าชมเห็นว่าเว็บไซต์มีการพัฒนาอยู่ตลอด

back-end หมายถึง ระบบจัดการเว็บไซต์ เปรียบได้กับหลังบ้าน ถือเป็นส่วนการจัดการเนื้อหารวมถึงโครงสร้างของเว็บไซต์ สำหรับให้ผู้ดูแลเว็บไซต์เข้ามาบริหารจัดการเว็บไซต์ จะเรียกกันสั้นๆว่า หลังบ้าน เช่น จัดการฐานข้อมูล โครงสร้างเว็บไซต์ การเขียนโค้ดควบคุม XML, text file, JAVA, PHP, C#, C++ เป็นต้น จะมีไว้สำหรับ admin หรือผู้ที่ได้รับอนุญาต เพื่อทำการ เพิ่ม ลบ แก้ไข เปลี่ยนแปลงเว็บไซต์ ในส่วนของ back-end มีความสำคัญเป็นอย่างยิ่ง ไม่ว่าจะเป็นการรักษาความปลอดภัยของข้อมูล ทั้ง username password ข้อมูลเว็บไซต์ต่าง ๆ รวมไปถึงการทำงานของเว็บไซต์ ความเร็วในการแสดงผล

Front-end และ Back-end เกี่ยวข้องกันอย่างไร

front-end กับ back-end จะมีความสำคัญต่อกันเป็นอย่างมาก หาก front-end แสดงผลช้าหรือเกิดข้อผิดพลาด ส่วนของ back-end ก็ต้องทำการแก้ไขปัญหา หรือถ้าหากว่า back-end ไม่ทำการปรับปรุงเว็บไซต์อย่างสม่ำเสมอ จะส่งผลต่อเว็บไซต์ไม่ว่าจะเป็น เว็บไซต์ล้าหลัง ขาดความน่าสนใจ ผู้เยี่ยมชมลดลง ก่อให้เกิดผลกระทบหลายๆด้าน

Front-end และ Back-end อะไรสำคัญกว่ากัน ?

ถ้าการใช้งานเว็บไซต์เน้นการแสดงข้อมูลที่ไม่เยอะ front-end จะต้อง design ให้ออกมาสวยและถูกใจคนเข้าชมเว็บไซต์ แต่ถ้าหากเว็บไซต์ข้อมูลเยอะ ส่วน back-end จะต้องจัดการข้อมูลและจัดการเว็บไซต์อย่างไรเพื่อไม่ให้ระบบนั้นช้าลงในการแสดงผล

2.8.1 โปรโตคอล HTTP และ HTTPS ในการสื่อสารระหว่างเบราว์เซอร์กับเว็บเซิร์ฟเวอร์

HTTP (HyperText Transfer Protocol) เป็นโปรโตคอลระดับแอปพลิเคชันที่เว็บเบราว์เซอร์ใช้ติดต่อกับเว็บเซิร์ฟเวอร์ ทำงานแบบคำขอ–การตอบกลับ (Request–Response) กล่าวคือ ฝั่ง Client เป็นฝ่ายส่งคำขอ และเซิร์ฟเวอร์ตอบกลับมาเสมอ (Mozilla Developer Network [MDN], 2024d) คำขอประกอบด้วยเมธอด (Method) เช่น GET สำหรับขอข้อมูล POST สำหรับส่งข้อมูล PUT สำหรับแก้ไข และ DELETE สำหรับลบ พร้อมที่อยู่ปลายทาง (URL) ส่วนหัว (Header) และเนื้อหา (Body) ถ้ามี ส่วนการตอบกลับประกอบด้วยรหัสสถานะ (Status Code) ส่วนหัว และเนื้อหา เช่น ไฟล์ HTML ที่เบราว์เซอร์นำไปแสดงผล

ตัวอย่างข้อความคำขอและการตอบกลับ

GET /index.html HTTP/1.1

โค้ด
Host: www.example.com
Accept: text/html

HTTP/1.1 200 OK

Content-Type: text/html; charset=UTF-8

โค้ด
<!DOCTYPE html>
<html lang="th"> ... </html>

รหัสสถานะแบ่งตามหลักแรกเป็น 5 กลุ่ม ได้แก่ 1xx ข้อมูลเบื้องต้น 2xx สำเร็จ (เช่น 200 OK, 201 Created) 3xx ให้ไปที่อื่น (เช่น 301 ย้ายถาวร, 302 ย้ายชั่วคราว) 4xx ข้อผิดพลาดจากฝั่ง Client (เช่น 400 คำขอไม่ถูกต้อง, 401 ยังไม่ยืนยันตัวตน, 403 ไม่มีสิทธิ์, 404 ไม่พบหน้า) และ 5xx ข้อผิดพลาดจากฝั่งเซิร์ฟเวอร์ (เช่น 500, 503) นักพัฒนาใช้แท็บ Network ใน DevTools ของเบราว์เซอร์ตรวจดูคำขอ รหัสสถานะ และส่วนหัวของแต่ละคำขอได้

HTTP เป็นโปรโตคอลแบบไม่เก็บสถานะ (Stateless) คือเซิร์ฟเวอร์ไม่จำว่าคำขอก่อนหน้าเป็นของใคร เว็บแอปพลิเคชันจึงใช้คุกกี้ (Cookie) และเซสชัน (Session) เพื่อระบุผู้ใช้ต่อเนื่อง ดังที่จะเรียนในบทที่ 7 ปัจจุบัน HTTP มีหลายเวอร์ชัน โดย HTTP/2 ส่งหลายคำขอผ่านการเชื่อมต่อเดียวกันเพื่อลดเวลารอ และ HTTP/3 ทำงานบน QUIC ซึ่งใช้ UDP ทั้งนี้เบราว์เซอร์และเซิร์ฟเวอร์เลือกเวอร์ชันที่รองรับร่วมกันโดยอัตโนมัติ นักพัฒนาเว็บทั่วไปไม่ต้องเปลี่ยนวิธีเขียนโค้ด

HTTPS (HTTP Secure) คือ HTTP ที่ส่งผ่านชั้นความปลอดภัย TLS (Transport Layer Security) โดยมีหน้าที่ 3 ประการ คือ เข้ารหัสข้อมูลระหว่างเบราว์เซอร์กับเซิร์ฟเวอร์เพื่อป้องกันการดักอ่าน ตรวจสอบว่าข้อมูลไม่ถูกแก้ไขระหว่างทาง และยืนยันตัวตนของเว็บไซต์ด้วยใบรับรองดิจิทัล (Digital Certificate) ที่ออกโดยผู้ออกใบรับรอง (Certificate Authority: CA) (Open Web Application Security Project [OWASP], 2023f) เมื่อเชื่อมต่อ เบราว์เซอร์และเซิร์ฟเวอร์จะตกลงรุ่นของ TLS และชุดการเข้ารหัส ตรวจใบรับรอง แล้วสร้างกุญแจลับร่วมสำหรับเข้ารหัสข้อมูลตลอดการสื่อสาร HTTP ใช้พอร์ต 80 ส่วน HTTPS ใช้พอร์ต 443 เป็นค่าเริ่มต้น

ปัจจุบันเว็บไซต์ที่มีแบบฟอร์มล็อกอินหรือรับข้อมูลส่วนบุคคลควรใช้ HTTPS เสมอ เพราะเบราว์เซอร์จะแจ้งเตือนว่า "ไม่ปลอดภัย" เมื่อหน้าที่มีช่องรหัสผ่านใช้ HTTP ธรรมดา และสอดคล้องกับมาตรการรักษาความมั่นคงปลอดภัยตาม PDPA (หัวข้อ 2.23) ผู้ให้บริการอย่าง Let's Encrypt ออกใบรับรองให้ฟรีแบบอัตโนมัติ (Internet Security Research Group [ISRG], 2024) ซึ่งจะนำไปตั้งค่าใช้งานจริงในบทที่ 10

2.9 แนะนำ Bootstrap

2) Base CSS style sheets สำหรับ html elements พื้นฐาน เช่น typography, tables, forms และ images เป็น Stylesheet พื้นฐานที่เราสามารถเรียกใช้งานได้เลย
3) Components style sheets สำหรับสิ่งที่่ต้องใช้บ่อย ๆ ไม่ว่าจะเป็น navigation, breadcrumbs รวมไปถึง pagination ที่เป็นตัวโครงสร้างพื้นฐานของบูทสแตรป ที่ไว้จัดการกับตัว Menu , Navigation ซึ่งจะแปรผันกบขนาดของหน้าจอ ของอุปกรณ์ที่เรียกใช้งาน

4) JavaScript jQuery plugins ง่าย ๆ ไม่ว่าจะเป็น modal, carousel หรือ tooltip ที่ช่วยในการสร้าง Popup, Dialog , Tooltip ง่าย ๆ ซึ่งสามารถเรียกใช้งานได้่ง่าย

ถึงแม่ว่า Bootstrap จะมีโครงสร้างพื้นฐานที่บังคับให้การออกแบบเป็นไปตาม Framework ออกแบบและที่มีมาให้ แต่เราก็สามารถที่จะเขียนพวก CSS และ Stylesheet เพิ่มเติม เพื่อเข้าไปจัดการกับ UI ต่าง ๆ ที่ต้องการได้ แต่ทั้งนี้จะต้องให้เข้าใจโครงสร้างของมันซะก่อน ไม่ฉะนั้นเมื่อนำไปใช้งานกับขนาดของอุกรณ์ต่าง ๆ อาจจะมีปัญหาในการแสดงผลได้

ในปัจจุบัน Bootstrap เฟรมเวิร์กสำหรับเขียนเว็บชื่อดัง ประกาศออกเวอร์ชัน 5.0 Alpha 1 มีการเปลี่ยนแปลงสำคัญคือเลิกใช้เฟรมเวิร์ก jQuery ที่ใช้มายาวนาน เปลี่ยนมาใช้โค้ด JavaScript ปกติแทน ด้วยเหตุผลว่าฟีเจอร์ของ JavaScript และเบราว์เซอร์รุ่นใหม่ๆ สามารถทดแทน jQuery ได้แล้ว

ผลของการเลิกใช้ JQuery ช่วยให้ขนาดไฟล์เว็บที่สร้างด้วย Bootstrap เล็กลง และเว็บเพจโหลดได้เร็วขึ้น ทีมงาน Bootstrap บอกว่ายังต้องปรับปรุงแก้ไขการแสดงผลอีกหลายจุดหลังถอด jQuery ออกไป ซึ่งก็จะค่อยๆ แก้ไขในรุ่นทดสอบถัดๆ ไป Bootstrap 5 ยังเลิกซัพพอร์ต Internet Explorer แล้ว ทำให้เรียกใช้ฟีเจอร์เว็บใหม่ๆ ได้ เช่น CSS custom properties

2.10 แนะนำ Responsive Web Design

Responsive Web Design คือ การออกแบบเว็บไซต์ด้วยแนวคิดใหม่ ที่จะทำให้เว็บไซต์ สามารถแสดงผลได้อย่างเหมาะสม บนอุปกรณ์ที่แตกต่างกัน โดยใช้ โค้ดร่วมกัน URL เดียวกัน เพื่อแก้ปัญหาดังกล่าว

ในปัจจุบัน Mobile Internet Users ได้มีจำนวนเพิ่มขึ้นอย่างรวดเร็ว และมีแนวโน้มที่จะแซง Desktop Internet Users ในปี 2013 อีกด้วย ซึ่ง Mobile Devices นั้นมีความหลากหลายมาก ไม่ว่าจะเป็น ขนาดและความละเอียดของหน้าจอแสดงผล (screen size and resolution) แนวของการแสดงผล (orientation) หรือแม้แต่ระบบปฏิบัติการ(OS)

ถ้าเป็นสมัยก่อน เราต้องทำเว็บไซต์ออกมาหลายๆ version เช่น Desktop version กับ Mobile version เพื่อให้เว็บไซต์ของเรา สามารถแสดงผลได้อย่างเหมาะสมกับ Device นั้นๆ ซึ่งวิธีนี้จะทำให้ต้นทุนเพิ่มขึ้น ทั้งในด้านเวลาและค่าจ้างในการพัฒนา

หลักการของ Responsive Web Design

การจะทำ Responsive Web Design มักใช้เทคนิคหลายๆ อย่าง ร่วมกัน ไม่ว่าจะเป็น Fluid Grid, Flexible Images และ CSS3 Media Queries

เริ่มแรกคือการทำ Fluid Grid ซึ่งก็คือการออกแบบ Grid ให้เป็นแบบ Relative ซึ่งก็คือการที่ไม่ได้กำหนดขนาดของ Grid แบบตายตัว แต่จะกำหนดให้สัมพันธ์กับสิ่งอื่นๆ เช่น กำหนดความกว้างแบบเป็น % หรือการใช้ font-size หน่วยเป็น em เป็นต้น

ต่อมาคือการทำ Flexible Images หรือการกำหนดขนาดของ Images ต่าง ๆ ให้มีความสัมพันธ์กับขนาดของหน้าจอแสดงผล หากรูปต้นฉบับมีขนาดใหญ่มาก เวลาแสดงในมือถือที่มีจอขนาดเล็ก ก็ควรลดขนาดลงมา เพื่อให้แสดงผลได้อย่างสวยงาม เป็นต้น

สุดท้ายคือการใช้ CSS3 Media Queries ซึ่งจะช่วยให้เราสามารถกำหนด style sheets สำหรับ Devices ต่าง ๆ ได้ โดยส่วนใหญ่ เราจะเขียน style sheets พื้นฐานเอาไว้ ซึ่งกลุ่มนี้ จะไม่ขึ้นอยู่กับ Devices ใดๆ หลังจากนั้นให้เราเขียน style sheets สำหรับ Devices ที่มีขนาดหน้าจอที่เล็กสุด เพิ่มขึ้นไปเรื่อยๆ จนถึงขนาดใหญ่สุด ซึ่งการเขียนแบบนี้ จะช่วยลดความซ้ำซ้อนของโค้ด และยังทำให้การแก้โค้ดในภายหลังทำได้ง่ายอีกด้วย

อย่างไรก็ตาม Responsive Web Design ก็ยังมีข้อเสียอยู่บ้าง เนื่องจากการเขียนโค้ดเดียว ให้รองรับหลายๆ Devices จึงอาจทำให้เกิดปัญหา เช่น โทรศัพท์มือถือที่มีหน้าจอขนาดเล็ก ถึงแม้เราจะซ่อนเนื้อหาบางส่วนที่ไม่จำเป็นเอาไว้ เช่น โฆษณา แต่ในบางเว็บเบราว์เซอร์ ข้อมูลเหล่านี้ยังจะถูกโหลดเข้ามาอยู่ รวมไปถึงเรื่องของ Image Resizing ที่เราไม่ได้ไปลด File Size ของตัว Image จริงๆ ทำให้โทรศัพท์มือถือจำเป็นต้องโหลดรูปเดียวกับรูปที่ใช้แสดงบน Desktop ทำให้เสียเวลาโดยไม่จำเป็น

Responsive Web Design มีทั้งข้อดีและข้อจำกัด ปัจจุบันมีความเข้าใจโดยทั่วไปว่า Responsive Web จะมาแทนที่ Mobile Web ได้ทั้งหมด แต่ในความเป็นจริงยังไม่ถูกต้องนัก เนื่องจาก Responsive Web ยังมีข้อจำกัดด้านประสิทธิภาพ (Performance) และข้อจำกัดทางเทคนิคบางประการ ทำให้ยังไม่สามารถทำได้ทุกอย่างเทียบเท่า Mobile Web เว็บไซต์ขนาดใหญ่ เช่น Facebook และ YouTube จึงยังมี Mobile Version เพื่อให้ผู้ใช้ได้รับประสบการณ์การใช้งานที่ดีที่สุด อุปมาได้ว่า Responsive Web เปรียบเหมือนเสื้อสูทแบบฟรีไซส์ ส่วน Mobile Web เปรียบเหมือนเสื้อสูทแบบสั่งตัด ดังนั้นผู้พัฒนาควรพิจารณาก่อนว่า Responsive Web ตอบสนองความต้องการของโครงการหรือไม่

ความสำคัญของ Responsive Web Design

1. ไม่ต้องเขียนโค้ด HTML 2 ชุด

จากที่แต่เดิมต้องเขียน HTML 2 ชุด แยกเป็น Desktop และ Mobile และเมื่อจะแก้ไข ตัดหรือเพิ่มบางอย่าง ก็ต้องแก้ไขโค้ดทั้ง 2 ชุด ทำให้ยุ่งยากและเสียเวลา

2. รองรับการใช้งานทุกอุปกรณ์

แม้เว็บไซต์ที่ไม่รองรับ Responsive Web Design จะสามารถใช้งานบนอุปกรณ์อื่นได้เหมือนกัน แต่จะมีขนาดที่ไม่เหมาะกับการใช้งาน ทำให้ผู้ใช้ต้องซูมเข้าซูมออกเพื่อดูภาพหรือตัวอักษร เกิดความไม่สะดวก และอาจไม่อยากกลับมาใช้งานเว็บไซต์อีก

3. รองรับ SEO

การทำ Responsive Web Design ส่งผลดีต่อคะแนนของ SEO (Search Engine Optimization) ทำให้เว็บไซต์ของเรามีโอกาสจัดอยู่ในลำดับที่ดีขึ้นของหน้า อย่าง Google

ปัจจุบัน เว็บไซต์ส่วนใหญ่ที่เราใช้งานเป็น Responsive Web Design กันแทบทั้งหมดแล้ว เพราะไม่อย่างนั้นอาจทำให้ผู้ใช้งานลดลงเนื่องจากความไม่สะดวกสบาย และการที่เว็บไซต์รองรับการใช้งานบนทุกอุปกรณ์ยังทำให้ง่ายต่อการทำตลาด เพราะไม่ว่าลูกค้าจะใช้อุปกรณ์อะไรอยู่ ก็สามารถคลิกเข้ามาใช้งานเว็บไซต์ของเราได้เลย

2.11 แนะนำ Web Service และสถาปัตยกรรม REST API (Fielding, 2000; Mozilla Developer Network [MDN], 2024d)

ในยุคที่ผู้ใช้เชื่อมต่อกันผ่านระบบเครือข่ายและรับส่งข้อมูลข่าวสารบนอุปกรณ์ต่าง ๆ ทั้งคอมพิวเตอร์ โทรศัพท์เคลื่อนที่ และอุปกรณ์อิเล็กทรอนิกส์อื่น ๆ ซึ่งอาจทำงานบนระบบปฏิบัติการต่างกัน พัฒนาด้วยภาษาโปรแกรมต่างกัน หรืออยู่ในสภาพแวดล้อมที่ต่างกัน แต่ก็สามารถรับส่งข้อมูลระหว่างกันได้ สิ่งที่เกี่ยวข้องกับการสื่อสารดังกล่าวคือ Web Service และ API ในหัวข้อนี้จึงอธิบายความหมายของทั้งสองคำและความแตกต่างระหว่าง Web Service กับ API

Web Service เป็นบริการบนเครือข่ายเว็บไซต์ที่ออกแบบมาเพื่อใช้เป็นช่องทางสื่อสารระหว่างอุปกรณ์อิเล็กทรอนิกส์กับอุปกรณ์อิเล็กทรอนิกส์อื่นๆ ซึ่งจะทำงานผ่านทาง The HTTP (Mozilla Developer Network [MDN], 2024d)

โดยการรับส่งข้อมูลของ Web Service จะนิยมใช้รูปแบบข้อมูล XML กับ JSON ซึ่งไม่ว่าระบบจะพัฒนาด้วยภาษาโปรแกรมใดๆ ก็สามารถอ่านข้อมูลและส่งกลับได้ โดยปกติการทำงานจะแบ่งเป็น 2 ฝั่ง คือ ฝั่งเซิร์ฟเวอร์ (Server) จะเตรียมช่องทางการทำงานที่จำเป็นให้ระบบที่เป็นฝั่งไคลเอนต์สามารถดึงข้อมูลไปใช้หรือส่งข้อมูลกลับมาได้ ส่วนฝั่งไคลเอนต์ (Client) จะสามารถเรียกใช้งานส่วนต่าง ๆ ได้เท่าที่ฝั่งเซิร์ฟเวอร์เปิดช่องทางไว้ให้เท่านั้น ซึ่งการทำงานหลักๆ ที่ Web Service ฝั่งเซิร์ฟเวอร์มักจะเปิดช่องทางไว้ให้ ได้แก่ การเข้าระบบ การเพิ่มข้อมูล การแก้ไขข้อมูล การอ่านข้อมูล และการลบข้อมูล โดยฝั่งไคลเอนต์อาจจะเป็นเครื่องคอมพิวเตอร์ มือถือ หรืออุปกรณ์อิเล็กทรอนิกส์อื่นๆ ก็ได้ที่สามารถทำงานผ่าน HTTP รูปแบบโมเดลสื่อสารของ Web Service นิยมใช้เป็น Representational state transfer (REST), Simple Object Access protocol (SOAP) และ XML-RPC

Application Programming Interface (API) เป็นช่องทางการสื่อสารคล้ายกับ Web Service แต่ไม่จำกัดอยู่เฉพาะบน HTTP สามารถใช้สื่อสารกันในระบบปฏิบัติการ ระบบฐานข้อมูล อุปกรณ์อิเล็กทรอนิกส์ หรือซอฟต์แวร์ต่าง ๆ ได้ทั้งแบบออนไลน์และออฟไลน์ เช่น การสื่อสารระหว่างซอฟต์แวร์ภายในอุปกรณ์อิเล็กทรอนิกส์ รูปแบบหรือโครงสร้างของ API พัฒนาได้หลายรูปแบบและหลายภาษาโปรแกรมตามลักษณะการใช้งาน เช่น API ที่ทำงานบนระบบปฏิบัติการ Windows พัฒนาด้วยภาษา C และ C++ ส่วนซอฟต์แวร์ชุด Office เช่น Word และ Excel ใช้ VBA และ COM API ในการสื่อสาร โดยทั่วไปผู้พัฒนามักจัดทำเอกสารหรือคู่มือการเรียกใช้ API เพื่ออำนวยความสะดวกแก่ผู้ใช้ สำหรับความสัมพันธ์ระหว่าง Web Service กับ API นั้น API ที่ทำงานบนเว็บไซต์เรียกว่า Web API หรือ Web Service

สรุปความแตกต่างระหว่าง Web Service กับ API

  • Web Service ทั้งหมดเป็น API แต่ตัว API ทั้งหมดไม่ใช่ Web Service
  • Web Service จำกัดการทำงานอยู่บน HTTP ไม่สามารถทำงานได้ในระบบปฏิบัติการหรือสภาพแวด ล้อมอื่นๆ แต่ API สามารถทำงานได้ในทุกระบบปฏิบัติการและสภาพแวดล้อม
  • รูปแบบการสื่อสารของ Web Service จะมีเพียงไม่กี่รูปแบบ เช่น SOAP, REST และ XML-RPC แต่ API สามารถใช้รูปแบบการสื่อสารได้หลากหลาย
  • Web Service จำเป็นต้องใช้ระบบเครือข่ายในการทำงาน แต่ API สามารถทำงานได้ทั้งแบบผ่านเครือข่ายและไม่ผ่านเครือข่าย
  • API สามารถสื่อสารกับส่วนต่าง ๆ ได้โดยตรงอย่างรวดเร็ว ส่วน Web Service การสื่อสารจะต้องผ่านหลายขั้นตอน รวมถึงต้องมีการแปลงข้อมูลให้อยู่ในรูปแบบ XML หรือ JSON ก่อนส่งข้อมูล และต้องแปลงข้อมูลกลับเมื่อจะนำไปใช้งานต่อในระบบ

2.12 แนะนำ jQuery

jQuery คือ JavaScript Library ซึ่งถูกออกแบบมาเพื่อให้การเขียน JavaScript นั้นมีความสะดวกและง่ายขึ้น เพราะว่าการนำ JavaScript เอาไปประยุกต์กับงานจำพวกเว็บ (Client-side JavaScript) นั้นเป็นสิ่งที่ยุ่งยาก ไม่ว่าจะเป็นเรื่องความไม่เข้ากันของ Web Browser แต่ละค่าย, DOM หรือ API เป็นต้น

ดังนั้น jQuery จึงรวบรวมออบเจกต์ (Object) และฟังก์ชัน (Function) ที่จำเป็นไว้ในรูปแบบไลบรารี ทำให้โค้ด JavaScript ที่ต้องเขียนหลายบรรทัดสามารถย่อให้สั้นลงได้ บางกรณีเหลือเพียงบรรทัดเดียว

jQuery ประกอบด้วยฟีเจอร์ต่าง ๆ ดังนี้

  • HTML/DOM manipulation
  • CSS manipulation
  • HTML event methods
  • Effects and animations
  • AJAX
  • Utilities

ก่อนเรียน jQuery ผู้เรียนควรมีความรู้เรื่อง HTML5, CSS3 และ JavaScript การใช้งานทำได้โดยอ้างอิงไลบรารีจากเครือข่ายส่งเนื้อหา (Content Delivery Network: CDN) ดังตัวอย่างต่อไปนี้ (ตัวอย่างใช้ jQuery 4.0.0 ซึ่งเป็นเวอร์ชันล่าสุดที่แสดงบนเว็บไซต์ทางการ jquery.com เมื่อวันที่ 8 พฤศจิกายน 2569 ควรตรวจสอบเวอร์ชันอีกครั้งก่อนใช้งานจริง)

โค้ด
<script src="https://code.jquery.com/jquery-4.0.0.min.js"></script>

jQuery syntax

jQuery ออกแบบมาให้เลือก HTML element และกำหนด action ให้กับเอลิเมนต์นั้น มี syntax ดังนี้

โค้ด
$(selector).action()             selector คือส่วนที่เลือก เช่น element , css

action() คือ เมธอดที่ใช้กำหนดการทำงานให้กับ selector

ตัวอย่าง เช่น

- $(this).hide() เป็นการซ่อนองค์ประกอบปัจจุบัน

- $("p").hide() เป็นการซ่อนองค์ประกอบ "p" ทั้งหมด

- $(".test").hide() เป็นการซ่อนองค์ประกอบที่มี class= "test"

- $("#test").hide() เป็นการซ่อนองค์ประกอบที่มี id="test"

ปัจจุบัน jQuery ยังพบในเว็บไซต์รุ่นเดิมและในระบบสำเร็จรูปบางระบบ แต่โครงการใหม่นิยมใช้ JavaScript มาตรฐานแทน เช่น document.querySelectorAll() และ Fetch API ซึ่งเบราว์เซอร์รองรับในตัวโดยไม่ต้องโหลดไลบรารีเพิ่ม ตัวอย่างเช่น คำสั่ง $("p").hide() เทียบได้กับ document.querySelectorAll("p").forEach((e) => (e.hidden = true)) ส่วน Bootstrap 5 ก็ไม่ต้องพึ่งพา jQuery อีกต่อไป

2.13 แนะนำ Ajax และ Fetch API

Ajax (Asynchronous JavaScript and XML) คือแนวทางการส่งและรับข้อมูลกับเซิร์ฟเวอร์ในพื้นหลังโดยไม่ต้องโหลดหน้าเว็บใหม่ทั้งหน้า ทำให้อัปเดตเฉพาะส่วนของหน้าได้ และผู้ใช้ไม่ต้องหยุดรอการประมวลผลของเซิร์ฟเวอร์ Ajax ไม่ใช่ภาษาโปรแกรมหรือเทคโนโลยีเดี่ยว แต่เป็นการทำงานร่วมกันของ JavaScript, DOM และการติดต่อเซิร์ฟเวอร์แบบอะซิงโครนัส
ในอดีตนิยมใช้ออบเจกต์ XMLHttpRequest และแลกเปลี่ยนข้อมูลในรูปแบบ XML ปัจจุบันนิยมใช้ Fetch API ซึ่งเป็นมาตรฐานของเบราว์เซอร์ ร่วมกับข้อมูลรูปแบบ JSON โดยฝั่งเซิร์ฟเวอร์เขียนด้วย PHP ส่งข้อมูลกลับมาด้วยฟังก์ชัน json_encode() เช่น ไฟล์ customer_json.php ต่อไปนี้ (ข้อมูลตัวอย่าง ในบทที่ 8 สามารถเปลี่ยนเป็นข้อมูลจากตาราง customer ของฐานข้อมูลได้)

โค้ด
<?php
header("Content-Type: application/json; charset=UTF-8");
$customers = [
    ["CustomerID" => "C001", "Name" => "สมชาย ใจดี"],
    ["CustomerID" => "C002", "Name" => "สมหญิง รักเรียน"],
];
echo json_encode($customers, JSON_UNESCAPED_UNICODE);

ฝั่งหน้าเว็บเรียกใช้ Fetch API เพื่อดึงข้อมูลจากไฟล์ดังกล่าวและนำมาแสดงผล ดังนี้

fetch("customer_json.php")
.then((res) => {
if (!res.ok) throw new Error("HTTP " + res.status);
return res.json();
})
.then((data) => {
data.forEach((c) => console.log(c.CustomerID, c.Name));
})
.catch((err) => console.error("เกิดข้อผิดพลาด", err));

2.14 แนะนำ XML

XML (เอ็กซ์เอ็มแอล) ย่อมาจาก Extensible Markup Language เป็นภาษามาร์กอัปที่ออกแบบมาเพื่อจัดเก็บและแลกเปลี่ยนข้อมูล โดยเก็บทั้งข้อมูลและโครงสร้างของข้อมูลไว้ด้วยกัน ต่างจาก HTML ซึ่งออกแบบมาเพื่อแสดงผลเอกสารบนเว็บ เช่น การแสดงตัวหนาและตัวเอียง XML มีโครงสร้างประกอบด้วยแท็กเปิดและแท็กปิดเช่นเดียวกับ HTML แต่ผู้ใช้สามารถกำหนดชื่อแท็กและโครงสร้างข้อมูลได้เอง ขณะที่ HTML มีแท็กที่กำหนดตายตัวโดย World Wide Web Consortium (W3C) ส่วนการแสดงผลข้อมูล XML ต้องใช้ร่วมกับภาษาหรือเทคโนโลยีอื่น เช่น XSL (Extensible Stylesheet Language) CSS หรือภาษาโปรแกรมฝั่งเซิร์ฟเวอร์อย่าง PHP ไฟล์ XML มีนามสกุล .xml และสร้างได้จากโปรแกรมแก้ไขข้อความ (Text Editor) ทั่วไป เช่น Notepad, EditPlus และ Dreamweaver ปัจจุบันการแลกเปลี่ยนข้อมูลบนเว็บนิยมใช้ JSON (ดูหัวข้อ 2.22) แทน XML เพราะอ่านง่ายและมีขนาดเล็กกว่า แต่ XML ยังใช้ในงานบางประเภท เช่น ฟีด RSS ไฟล์ sitemap.xml และภาพ SVG

2.15 แนะนำ DOM

DOM (Document Object Model) คือการจัดเอกสาร HTML ให้อยู่ในรูปแบบของ DOM Tree โดยนิยาม objects และ properties เพื่อให้โปรแกรมหรือสคริปต์ สามารถปรับเปลี่ยนโครงสร้าง, ข้อมูล และ styles ของ HTML DOM ผ่าน methods ได้ DOM แบ่งออกเป็น 3 ส่วน Core DOM – การจัดรูปแบบ DOM Tree สำหรับทุกๆ เอกสาร

HTML DOM เป็นหัวข้อพื้นฐานสำคัญสำหรับนักพัฒนาเว็บ แม้จะมีการใช้งานบ่อยครั้ง เช่น document.getElementById("element"); แต่ผู้พัฒนาจำนวนมากยังไม่ทราบแนวคิดของ DOM

ไม่ควรมองข้ามเรื่อง DOM เนื่องจากเป็นพื้นฐานสำคัญในการพัฒนาเว็บยุคใหม่ ไลบรารี JavaScript จำนวนมากสร้างเมธอดครอบ DOM ไว้ ตัวอย่างเว็บไซต์ที่ใช้ไลบรารี JavaScript ได้แก่ Twitter, Facebook และ WordPress เป็นต้น

ปัญหาสำคัญของโปรแกรมเมอร์ส่วนใหญ่คือ แก้ไขหรือปรับปรุง JavaScript Library เองไม่ได้ เพราะไม่มีพื้นฐานที่ดีใน JavaScript และ HTML DOM มีหลายๆ คนปฏิเสธ JavaScript ไปเลยก็มี เด็กจบใหม่ส่วนใหญ่มีความเชื่อผิดๆ ว่า JavaScript เป็นภาษาที่ใช้สร้างลูกเล่นในเว็บ ไม่ได้มีความสำคัญอะไร และเป็นสคริปต์ที่น่ารำคาญ เพราะทุกครั้งที่เปิดไดอารี่ออนไลน์ของเพื่อน ชอบมี popup ขึ้นมาบ่อยๆ เพียงแค่มุมมองเล็กๆ ที่อคติ เราอาจจะพลาดโอกาสสำคัญๆ ที่จะเรื่องรู้อะไรใหม่ได้

DOM แบ่งออกเป็น 3 ส่วน

  • Core DOM – การจัดรูปแบบ DOM Tree สำหรับทุกๆ เอกสาร
  • XML DOM – การจัดรูปแบบ DOM Tree สำหรับเอกสาร XML
  • HTML DOM – การจัดรูปแบบ DOM Tree สำหรับเอกสาร HTML

เป็นการเปรียบเทียบเอกสาร HTML เมื่อจัดรูปแบบเป็น DOM Tree ซึ่งมีลักษณะคล้ายรากต้นไม้ที่แตกสาขา แต่ละกล่องเรียกว่าโหนด (Node) ดังแสดงในภาพด้านล่าง เรียกว่า DOM Node Tree

DOM Node Tree คืออะไร
คือการนิยามแต่ละโหนดใน DOM Node Tree โดยมีคำศัพท์ที่เกี่ยวข้อง เช่น Node Parents, Children และ Siblings ซึ่งอธิบายได้ดังนี้

ใน Node Tree หนึ่ง ๆ (หนึ่งเอกสาร HTML) จะมีโหนดที่อยู่บนสุดเพียงโหนดเดียว เรียกว่า Root

ทุกโหนดยกเว้น Root ต้องมี Parent Node หนึ่งโหนด

ใน 1 Node จะมีหรือไม่มีลูก (Children) ก็ได้

Leaf คือโหนดที่ไม่มีโหนดลูก (Children) กล่าวคือมีจำนวนโหนดลูกเท่ากับ 0

Siblings คือ Nodes ที่มี Parent Node เดียวกัน (เป็นพี่น้องกันนี่เอง)

HTML DOM Properties และ Methods
ยกตัวอย่างบางส่วนของ properties มาให้เห็นกัน สมมติ Node x คือ Tag H1

x.innerHTML – แทนที่ข้อมูลใน Node x ด้วย Tag HTML โดย method นี้จะ compile Tag HTML ให้

x.innerText – แทนที่ข้อมูลใน Node x ด้วย Text ธรรมดา โดย method นี้จะไม่ compile Tag HTML ให้ ถ้าใส่ Tag HTML ตัวมันเองจะมองว่าเป็นเพียงแค่ Text

x.nodeName – ชื่อของ Node x คือ “H1”

x.parentNode – parent node ของ x คือ “BODY”

x.childNodes – child nodes ของ x (ลูกของ H1 คือ #text, #text คือ Text Node)

x.nodeValue – value ของ x คือ null แต่ value ของ #text ซึงเป็นลูกของ x คือ “My header”

ยกตัวอย่างบางส่วนของ methods

x.getElementById(id) – เกทอิลิเมนต์ด้วย id ที่เรากำหนด, และ id ต้องมีหนึ่งเดียวในเอกสาร HTML

x.getElementsByTagName(name) – เกทอิลิเมนต์ด้วยชื่อ Tag ตามที่เรากำหนด ผลลัพธ์ที่ได้จะเป็น array ของ object เวลาเราจะอ้างอิงแต่ละ object คือ x.getElementsByTagName(“DIV”)[i].nodeType, i มีค่าได้ตั้งแต่ 0-n โดย n < x.getElementsByTagName("DIV").length

Tip-Trick ในการจำ ถ้า methods ใด มี keyword แบบนี้ “getElements” ผลลัพธ์ที่ได้ต้องเป็น array

x.appendChild(node) – แทรก child node ใน x เช่น x.appendChild(document.createTextNode (““); คือ การสร้าง Text Node แทรกใน Node x

x.removeChild(node) – ลบโหนดลูก (child node) ออกจาก x เช่น x.removeChild(x.firstChild) หลังจากแทรก Text Node ใหม่ใน x แล้ว x จะมีโหนดลูก 2 โหนด เมื่อลบโหนดลูกตัวแรกออก ซึ่งคือ #text ที่มีค่าเท่ากับ "My header" ใน Tag H1 จะเหลือเฉพาะ #text ที่มีค่าเท่ากับ "ลงทุนกับสลากออมสิน" เพียงโหนดเดียว

2.16 แนะนำเฟรมเวิร์กสำหรับการพัฒนาเว็บ (Web Frameworks)

Framework อาจหมายถึง ชุดคำสั่ง เครื่องมือ หรือโครงสร้างอย่างใดอย่างหนึ่ง
ที่สร้างขึ้นมาเพื่ออำนวยความสะดวกแก่ผู้ใช้งาน ซึ่ง Framework มีหลายประเภท หลายแบบ และจะมีวิธีการใช้ที่คล้ายๆกัน

ข้อดีของ Framework

  • รวดเร็ว
  • ทำงานเป็นทีมได้
  • เหมาะกับองค์กรใหญ่ ๆ

ข้อเสียของ Framework

  • มีขนาดของ source โดยรวมใหญ่กว่าที่ควรจะเป็น เพราะบางอย่างเราไม่จำเป็นต้องใช้ แต่ว่ามันดันมีใน Framework
  • ต้องมีเวลาในการศึกษาFramework
  • การพัฒนาระบบอาจไม่เป็นไปตามที่ต้องการ
  • อาจมีคำถามเกิดขึ้นว่าเราพัฒนาระบบให้เป็นไปตามที่เราต้องการหรือว่าเราพัฒนาระบบให้เป็นไปตามFrameworkที่เราใช้

ประโยชน์ของ Framework

Framework เป็นเครื่องมือที่เป็นประโยชน์สำหรับโปรแกรมเมอร์และนักพัฒนาเพื่อใช้ในการสร้างเว็บไซต์และแอปพลิเคชันอื่นๆ ประโยชน์บางประการของ Framework มีดังต่อไปนี้

  • ประหยัดเวลาและแรงงานของผู้พัฒนาซอฟต์แวร์
  • Framework ได้จัดเตรียมชุดคำสั่งพื้นฐานเพื่อให้โปรแกรมเมอร์นำไปพัฒนาต่อยอดได้
  • ช่วยให้ผู้พัฒนาสามารถมุ่งเน้นไปที่งานที่เฉพาะเจาะจงมากขึ้นสำหรับโปรเจกต์ของผู้พัฒนา
  • สร้างชุดคำสั่งที่เป็นระเบียบและสามารถปรับเปลี่ยนได้
  • ช่วยลดค่าใช้จ่ายโดยย่นระยะเวลาในการพัฒนาโปรแกรม

การสร้างเว็บแอปพลิเคชันในส่วนของส่วนต่อประสานผู้ใช้ (User Interface) ในปัจจุบันมีความซับซ้อนมากกว่าในอดีต เนื่องจากผู้ใช้เข้าถึงเว็บไซต์ผ่านสมาร์ตโฟน แท็บเล็ต หรือแล็ปท็อปได้โดยง่าย เว็บแอปพลิเคชันจึงมีความซับซ้อนในการใช้งานเพิ่มขึ้น และการพัฒนาทำได้ยากกว่าเดิม จึงมีการพัฒนาเครื่องมือเพื่อช่วยลดภาระของนักพัฒนา คือ Front-End Framework ซึ่งช่วยให้เขียนโค้ดได้รวดเร็ว ประหยัดเวลา และช่วยด้านประสิทธิภาพ (Performance) ให้ทำงานได้ลื่นไหลเหมือนแอปพลิเคชันทั่วไป

ภายหลังทำความเข้าใจ Front-End Framework เบื้องต้นแล้ว ต่อไปนี้เป็น Framework ที่ได้รับความนิยมพร้อมข้อดีและข้อเสียของแต่ละตัว

  • มี community ที่ดีและการอัปเดตจากทีมวิศวกรของ facebook

  • เป็นแค่ UI library หากต้องการอย่างอื่นต้องหา third party library ติดตั้งเพิ่มเติมเอง

ส่วนงานที่มีขนาดเล็กก็ยังสามารถใช้เครื่องมือ JavaScript, HTML, CSS ในการพัฒนาได้โดยไม่ต้องพึ่ง framework โดยอาจจะเพียงแค่ใช้ส่วนเพิ่มเติมในการเข้ามาช่วยทำงานบางอย่าง เช่น การติดตั้ง Bootstrap เพื่อช่วยในส่วนของ responsive หรือตัวอื่น ๆ ที่เป็นที่นิยมอย่าง Material UI เป็นต้น

Web Framework การพัฒนาเว็บไซต์โดยใช้ Web Framework หมายถึง การพัฒนาเว็บไซต์โดยอาศัยชุดคำสั่ง รูปแบบการทำงาน โครงสร้าง ความปลอดภัย การเข้ารหัส และอื่น ๆ ที่ถูกพัฒนาเพิ่มมาจากภาษาหลักหรือ Core PHP การพัฒนาเว็บไซต์ในรูปแบบนี้ มีข้อดีอยู่มากมาย ช่วยประหยัดเวลาการทำงานเป็นอย่างมากหรืออาจจะเจอปัญหาในการพัฒนาเว็บไซต์ขนาดใหญ่ที่ต้องใช้นักพัฒนามากกว่าหนึ่งคน ปัญหาเหล่านี้จะหมดไปถ้าเป็นการพัฒนาเว็บไซต์ด้วย

ข้อดีอีกอย่างหนึ่งของการพัฒนาเว็บไซต์ด้วย Web Framework คือการป้องกันข้อผิดพลาดต่าง ๆ ที่อาจจะเกิดขึ้นจากการเขียนโค๊ดของนักพัฒนาเอง เนื่องด้วยเฟรมเวิร์กแต่ละตัวจะมีกรอบการทำงานไว้ให้เราอยู่แล้ว เมื่อมีการเขียนคำสั่งที่ผิดไปจากกรอบนั้น เพื่อป้องกันข้อผิดพลาดต่าง ๆ ระบบจะไม่ให้รันโปรแกรมผ่านได้
ตัวอย่าง Framework ที่น่าสนใจเช่น

  • PHP Laravel Framework
  • PHP CodeIgniter Framework
  • PHP Ruby on Rails (RoR) Framework

2.17 แนะนำสถาปัตยกรรม MVC (Model-View-Controller) (Krasner & Pope, 1988; จีราวุธ วารินทร์, 2566)

MVC (Model-View-Controller) เป็นรูปแบบ (Pattern) การเขียนโค้ดที่ได้รับความนิยมอย่างมาก ในโครงการขนาดเล็กที่มีฟังก์ชันน้อยอาจยังไม่เห็นประโยชน์ของการเขียนโค้ดตามรูปแบบนี้ แต่เมื่อโครงการมีฟังก์ชันมากขึ้น หรือต้องกลับมาแก้ไขโค้ดที่ไม่ได้จัดรูปแบบหลังจากเว้นระยะเวลานาน จะอ่านและบำรุงรักษาได้ยาก การเขียนโค้ดตามรูปแบบ MVC ซึ่งแยกส่วนการทำงานอย่างชัดเจน จึงช่วยให้อ่านโค้ดง่ายขึ้นและจัดการโค้ดได้อย่างเป็นระบบ

แนวคิดของ MVC

แนวคิดของ MVC ใช้หลักการของการเขียนโปรแกรมเชิงวัตถุ (OOP) โดยแบ่งการทำงานหลักเป็นออบเจกต์ 3 ส่วนตามชื่อ ได้แก่ Model View และ Controller ซึ่งมีหลักการคือแต่ละส่วนต้องแยกหน้าที่ออกจากกันอย่างชัดเจน ไม่ก้าวก่ายหน้าที่ของกันและกัน

หน้าที่ และ ความสำคัญของแต่ละส่วน

  • Model การทำงานของ model จะจัดการส่วนที่ข้อมูลทั้งหมดจะคอยเตรียมข้อมูลที่เหมาะสมไว้ และ model นั้นจะทำงานเมื่อ controller ร้องขอเท่านั้น
  • View เป็นการจัดการส่วนของหน้าตาทั้งหมด หรือส่วนติดต่อกับผู้ใช้โดยตรง (user interface) โดย view นั้นจะรับคำสั่งการทำงานจาก controller และเป็นตัวกลางให้ผู้ใช้ติดต่อกับ controller อีกด้วย
  • Controller เปรียบเสมือนกับมันสมองและศูนย์กลางการทำงานทั้งหมด จะเห็นว่าทุกส่วนนั้นจะติดต่อกับ controller ทั้งหมดรอคอยคำสั่งจาก controller นอกจากนี้ controller จะจัดการทำงานในส่วนที่เป็น logic ทั้งหมดในระบบ

การประยุกต์ใช้งาน MVC

เพื่อให้เห็นภาพการทำงานของแต่ละส่วนชัดเจนยิ่งขึ้น ขอยกตัวอย่างการเข้าสู่ระบบ (Login) ของเว็บไซต์ทั่วไป

  • เริ่มจากผู้ใช้จะติดต่อ V จากนั้น V จะไปบอกกับ C
  • C เมื่อได้รับข้อความจาก V จะส่งข้อมูลไปหา M เพื่อตรวจสอบความถูกต้อง
  • เมื่อ M ได้ยินดังนั้นจึงติดต่อฐานข้อมูลเพื่อตรวจสอบข้อมูลแล้วส่งผลกลับไปหา C
  • เมื่อ C ได้ผลการตรวจสอบมาก็จะดำเนินงานในขั้นต่อไป โดยที่มี2กรณีคือ
  • การลงชื่อเข้าใช้สำเร็จ : C สั่งการให้ V ติดต่อผู้ใช้โดยเปลี่ยนหน้าเว็บเป็นหน้าเว็บหลัก
  • การลงชื่อเข้าใช้ไม่สำเร็จ : C สั่งการให้ V ติดต่อผู้ใช้โดยบอกผู้ใช้ว่า รหัสผ่าน ผิดพลาด

ผู้เรียนควรทดลองนำรูปแบบ MVC ไปประยุกต์ใช้กับการเขียนโค้ดของตนเอง เช่น วิเคราะห์ว่าโครงงานของตนสามารถแบ่งการทำงานเป็น MVC ได้อย่างไร หรือนำไปใช้จริง การใช้รูปแบบ (Pattern) ในการเขียนโค้ดมีประโยชน์ทั้งช่วยให้ผู้พัฒนากลับมาอ่านโค้ดของตนได้ง่ายขึ้น ทำให้โค้ดเป็นระบบและจัดการได้ง่าย และกำหนดแบบแผนให้ผู้ร่วมทีมทำงานไปในทิศทางเดียวกัน

2.18 แนะนำ CMS

CMS (Content Management System) คือระบบการจัดการเนื้อหาของเว็บไซต์ เป็นระบบที่พัฒนา คิดค้นขึ้นมาเพื่อช่วยลดทรัพยากรในการพัฒนา(Development) และบริหาร(Management)เว็บไซต์ ไม่ว่าจะเป็นเรื่องของกำลังคน ระยะเวลา และเงินทอง ที่ใช้ในการสร้างและควบคุมดูแลไซต์โดยส่วนใหญ่แล้ว มักจะนำเอา ภาษาสคริปต์(Script languages) ต่าง ๆมาใช้ เพื่อให้วิธีการทำงานเป็นแบบอัตโนมัติ ไม่ว่าจะเป็น , , ASP, หรือภาษาอื่นๆ(แล้วแต่ความถนัดของผู้พัฒนา) ซึ่งมักต้องใช้ควบคู่กันกับโปรแกรมเว็บเซิร์ฟเวอร์(เช่น ) และดาต้าเบสเซิร์ฟเวอร์(เช่น )

ลักษณะเด่นของ CMS ก็คือ มีส่วนของ Administration panel(เมนูผู้ควบคุมระบบ) ที่ใช้ในการบริหารจัดการส่วนการทำงานต่าง ๆในเว็บไซต์ ทำให้สามารถบริหารจัดการเนื้อหาได้อย่างรวดเร็ว และเน้นที่การ จัดการระบบผ่านเว็บ(Web interface) ในลักษณะรูปแบบของ ระบบเว็บท่า(Portal Systems) โดยตัวอย่างของฟังก์ชันการทำงาน ได้แก่ การนำเสนอบทความ (Articles), เว็บไดเรคทอรี (Web directory), เผยแพร่ข่าวสารต่าง ๆ(News), หัวข้อข่าว(Headline), รายงานสภาพดินฟ้าอากาศ (Weather), ข้อมูลข่าวสารที่น่าสนใจ(Informations), ถาม/ตอบปัญหา(FAQs), ห้องสนทนา(Chat), กระดานข่าว(Forums), การจัดการไฟล์ในส่วนดาวน์โหลด (Downloads), แบบสอบถาม(Polls), ข้อมูลสถิติต่าง ๆ(Statistics) และส่วนอื่นๆอีกมากมาย ที่สามารถเพิ่มเติม ดัดแปลง แก้ไขแล้วประยุกต์นำมาใช้งานให้เหมาะสมตามแต่รูปแบบและประเภทของเว็บไซต์นั้นๆ

การประยุกต์ใช้ CMS

ระบบ CMS สามารถนำมาประยุกต์ในงานต่าง ๆ หลากหลาย ตัวอย่างการนำซอฟต์แวร์ CMS มา

ประยุกต์ใช้งาน อาทิเช่น

  • การนำ CMS มาใช้ในการสร้างเว็บไซต์สถาบันการศึกษา ธุรกิจบันเทิง หนังสือพิมพ์ การเงิน การธนาคาร หุ้นและการลงทุน อสังหาริมทรัพย์ งานบุคคล งานประมูล สถานที่ท่องเที่ยว งานให้บริการลูกค้า
  • การนำ CMS มาใช้ในหน่วยงานของรัฐ อาทิเช่น งานข่าว งานประชาสัมพันธ์ การนำเสนองานต่าง ๆขององค์กร
  • การใช้ CMS สร้างไซต์ ส่วนตัว ชมรม สมาคม สมาพันธ์ โดยวิธีการแบ่งงานกันทำ เป็นส่วนๆ ทำให้เกิดความสามัคคี ทำให้มีการทำงานเป็นทีมเวิร์คมากยิ่งขึ้น
  • การนำ CMS มาใช้ในการสร้างเว็บไซต์สำหรับธุรกิจ SME โดยเฉพาะสินค้าหนึ่งตำบลหนึ่งผลิตภัณฑ์หรือ OTOP กำลังได้รับความนิยมสูง
  • การนำ CMS มาใช้แทนโปรแกรมลิขสิทธิ์ อื่นๆ เพื่อประหยัดค่าใช้จ่าย และง่ายต่อการพัฒนา
  • การใช้ CMS ทำเป็น Intranet Web Site สร้างเว็บไซต์ใช้ภายในองค์กร

2.19 ยุคสมัยของเทคโนโลยีเว็บไซต์

การแบ่งยุคของเว็บเป็นการจำแนกเชิงแนวคิด ช่วงปีที่ระบุเป็นค่าประมาณ และแต่ละแหล่งข้อมูลกำหนดช่วงเวลาไม่เท่ากัน (Aghaei et al., 2012)

(ราว ค.ศ. 1990 – 2004) Web 1.0

เว็บ 1.0 ผลงานการคิดค้นของ ทิม เบิร์นเนอร์-ลี เป็นเทคโลยีเว็บไซต์ยุคแรกเริ่ม ที่หลายคนเรียกว่าเว็บยุค Read-Only Web หรือ อ่านได้อย่างเดียว ถือกำเนิดครั้งแรกในปี 1990 และเริ่มเสื่อมความนิยมราวปี 2004 ยุคนี้ คือเทรนด์ของการสื่อสารแบบทางเดียว (One Way Communication) ผู้ใช้งานอินเทอร์เน็ตส่วนใหญ่เป็นเพียงผู้บริโภคเนื้อหาไม่ใช่ผู้ผลิต ซึ่งเนื้อหาบนหน้าเว็บไซต์ต่าง ๆ มีเพียง Webmaster หรือผู้ดูแลเว็บเท่านั้นที่สามารถอัปเดตหรือจัดการในส่วนของเนื้อหาและข้อมูลต่าง ๆ ได้ ยังไม่มีการให้ผู้ใช้พิมพ์ข้อความ ความคิดเห็น หรือการโต้ตอบใดๆ ได้ ตัวอย่างหน้าเว็บไซต์ประเภทนี้ที่ยังมีการใช้งานอยู่ในปัจจุบัน เช่น เว็บไซต์ประกาศข่าว เว็บไซต์ประกาศรับสมัครงาน หรือ เว็บไซต์ประวัติส่วนตัว เป็นต้น ซึ่งอาจหลงเหลืออยู่ไม่มากแล้วในโลกของเวิล์ดไวด์เว็บ

(ตั้งแต่ ค.ศ. 2004) Web 2.0

Web 2.0 เริ่มต้นในปี 2004 ซึ่งหลายคนเรียกว่าเป็นเว็บยุค Read-Write Web ซึ่งก็คือรูปแบบส่วนใหญ่ ของเว็บไซต์ที่ใช้งานอยู่ในปัจจุบัน กล่าวคือ เป็นยุคที่การสื่อสารแบบสองทาง (Two Way Coummnication) บนโลกอินเทอร์เน็ตได้ถือกำเนิดขึ้น อันนำมาซึ่งการเปลี่ยนแปลงต่าง ๆ มากมาย เช่น การเกิดขึ้นของเว็บไซต์อีคอมเมิร์ซทั้งหลาย การช้อปปิ้งออนไลน์ได้กลายเป็นหนึ่งในไลฟ์สไตล์ยอดนิยม รวมถึง การแบ่งปันภาพถ่ายและวิดีโอ ตลอดจนเป็นยุคแรกของโซเชียลมีเดีย และ แพลตฟอร์มแชท ในตำนานต่าง ๆ อาทิ ICQ , MySpace , Hi5 หรือ แม้แต่ Facebook และ Twitter (ใครทัน ICQ กับ MySpace น่าจะเป็นรุ่นใหญ่แล้ว 555 ) ตลอดจนเทคโนโลยีทางการเงิน และอื่นๆ อีกมากมายกล่าวคือ บนแพลตฟอร์ม Web 2.0 ผู้ใช้สามารถสร้างเนื้อหาต่าง ๆ ให้ปรากฎยังฟอรัม ไซต์เครือข่ายสังคม ไซต์แบ่งปันรูปภาพ หรือ บล็อกได้อย่างอิสระ ซึ่งในช่วง 15 ถึง 20 ปีที่ผ่านมา หน้าเว็บไซต์รูปแบบเดิมๆ ของ Web 1.0 ได้ถูกแทนที่ด้วย Web 2.0 เกือบทั้งหมดแล้ว นอกจากนี้ นวัตกรรมด้านฮาร์ดแวร์ เช่น สมาร์ทโฟน แท็บเล็ต และการเข้าถึงอินเทอร์เน็ตบนมือถือได้ขับเคลื่อนการเติบโตให้แก่ Web 2.0 อย่างก้าวกระโดดเลยทีเดียว

(ตั้งแต่ ค.ศ. 2006 เป็นต้นมา) Web 3.0 หรือเว็บเชิงความหมาย (Semantic Web) (Berners-Lee et al., 2001; Markoff, 2006) ถูกยกให้เป็น “The Next Era of the Internet” ด้วยคุณสมบัติและความอัจฉริยะที่เพิ่มมากขึ้น กล่าวคือ เว็บไซต์และแอปต่าง ๆ จะสามารถประมวลผลข้อมูลได้อย่างชาญฉลาดใกล้เคียงมนุษย์ ผ่านเทคโนโลยีต่าง ๆ เช่น Machine Learning (ML) ปัญญาประดิษฐ์ (AI) ข้อมูลขนาดใหญ่ (Big Data) ตลอดจนเทคโนโลยีแยกประเภทแบบใช้ร่วมกัน (DLT) ซึ่งเป็นโครงสร้างดิจิทัลที่ใช้สำหรับการ จัดทำเอกสาร/บันทึกธุรกรรม ของสินทรัพย์ในหลายที่พร้อมกัน ซึ่งแตกต่างจากฐานข้อมูลดั้งเดิม โดยมีการใช้ระบบรักษาความปลอดภัยด้วยเทคโนโลยีบล็อคเชนเพื่อเก็บข้อมูลของผู้ใช้งานให้ปลอดภัยยิ่งขึ้น เป็นต้น แนวคิดเบื้องต้นของ Web 3.0 คือ ความเข้าใจและการตีความบริบทและแนวคิดของข้อมูลจากผู้ใช้งาน

ดังนั้นเมื่อผู้ใช้ค้นหาข้อมูลจากเว็บไซต์ เว็บ 3.0 จะให้ผลลัพธ์ที่ถูกต้องและเกี่ยวข้องมากที่สุดแก่ผู้ใช้ ซึ่งช่วยให้เว็บไซต์และแอปพลิเคชันต่าง ๆ ใช้ข้อมูลได้อย่างมีความหมายมากขึ้น และปรับข้อมูลให้เหมาะสมกับผู้ใช้แต่ละราย ทำให้ผู้ใช้โต้ตอบกับอุปกรณ์และเว็บไซต์ในลักษณะใกล้เคียงกับการสื่อสารระหว่างมนุษย์ นอกจากนี้ ประสบการณ์ที่แตกต่างที่สำคัญของ Web 3.0 คือ ผู้ใช้ไม่เพียงอ่านและเขียนข้อมูลได้ แต่ยังสามารถร่วมเป็นเจ้าของเว็บไซต์ได้ด้วย ซึ่งหมายถึงการมีส่วนร่วมในการบริหารเว็บไซต์หรือแพลตฟอร์ม

คุณสมบัติหลักของ Web 3.0

ขอเท็จจริงที่แน่นอน ของ Web 3.0 คือ ความสามารถในการจัดระเบียบข้อมูลได้สมเหตุสมผลกว่า Web 2.0 ซึ่งต่อไปนี้เป็นลักษณะสำคัญ 5 ประการ ที่จะช่วยอธิบาย ความเป็น Web 3.0 ได้ชัดเจนยิ่งขึ้น

1. Semantic Web

หรือเว็บเชิงความหมาย (Semantic Web) ซึ่งช่วยปรับปรุงเทคโนโลยีออนไลน์ให้ผู้ใช้สร้าง แบ่งปัน และเชื่อมโยงเนื้อหาผ่านการค้นหาและการวิเคราะห์ โดยอาศัยความสามารถในการเข้าใจความหมายของคำมากกว่าการอาศัยคำหลักหรือตัวเลข ตัวอย่างเช่น เว็บ 3.0 สามารถเชื่อมโยงและตีความเรื่องต่าง ๆ ตามบริบทได้ถูกต้องมากขึ้น เมื่อผู้ใช้พิมพ์คำว่า "โลกกลม" ระบบจะเข้าใจว่าผู้ใช้สนใจประเด็น "ความบังเอิญที่เพื่อนใหม่รู้จักกับเพื่อนเก่า" หรือประเด็น "ข้อสงสัยเรื่องรูปทรงของโลก" เป็นต้น

2. เทคโนโลยี AI

ด้วยเทคโนโลยี AI ที่ก้าวล้ำที่ถูกเสริมเข้ามาใน Web3.0 ส่งผลให้ Machine ต่าง ๆ สามารถเรียนรู้วิธีการคิดได้ซับซ้อนใกล้เคียงมนุษย์มากยิ่งขึ้น หรืออาจทำได้ดีกว่ามนุษย์ในบางเรื่อง ยกตัวอย่างเช่น เมื่อเราค้นหา คำว่า “Flight to Korea” ใน Google ระบบจะคิดเผื่อต่อยอดมาให้เราเลยว่ามีเมืองไหนบ้างในโซนนั้นที่คนนิยมเดินทางไป รวมถึงข้อมูลในรายละเอียดของเวลาที่ต้องใช้ในการเดินทางจากจุดที่เราอยู่ ตลอดจนบอกเรทราคาเริ่มต้นในการเดินทาง เป็นต้น

3. ความสามารถในการเชื่อมต่อ หรือ การมีอยู่ทุกหนแห่ง (Connectivity or Ubiquity)

Web 3.0 จะขจัดข้อด้อยต่าง ๆ ของ Web 2.0 ส่งผลให้ข้อมูลต่าง ๆ สามารถเชื่อมโยงกับ Web 3.0 ได้ดียิ่งขึ้น ด้วยเหตุนี้ ประสบการณ์ของผู้ใช้จึงก้าวไปสู่ระดับใหม่ของการเชื่อมต่อที่ใช้ประโยชน์จากข้อมูลที่เข้าถึงได้ทั้งหมด กล่าวคือ Web 3.0 จะใช้เซ็นเซอร์ IoT เป็นหลัก และทำให้ทุกคนสามารถใช้อินเทอร์เน็ตได้ทุกที่ ทุกเวลา (Ubiquity) และเมื่ออินเทอร์เน็ตเข้าถึงได้ทุกที่ทุกเวลา การเชื่อมต่อสิ่งต่าง ๆ ก็จะรวดเร็วขึ้น ในอนาคตการเชื่อมต่ออุปกรณ์อย่าง IoT ก็ไม่จำเป็นที่จะต้องเชื่อมผ่านคอมพิวเตอร์หรือโทรศัพท์สมาร์ทโฟนเหมือนกับยุค Web 2.0 อีกต่อไป

4. ซอฟต์แวร์สื่อสารกันเอง (Software negotiating with software)

ใน Web2.0 “เบราว์เซอร์และเว็บไซต์” มีปลั๊กอินหรือส่วนขยาย (Add-on) ของเบราว์เซอร์ที่ช่วยเหลือเราในเรื่องต่าง ๆ เช่น การกรอกรหัสผ่าน และการบล็อกโฆษณาต่าง ๆ เป็นต้น ด้วยเหตุนี้ซอฟต์แวร์ที่ตอบสนองต่อผู้ใช้แบบเรียลไทม์อาจทำให้เว็บไซต์ตอบสนองล่าช้าไปบ้างแต่ใน Web 3.0 จะแตกต่างออกไป เบราว์เซอร์จะเป็นเหมือนระบบปฏิบัติการประเภทหนึ่งที่ใช้รันโปรแกรม ซึ่งปลั๊กอินหรือส่วนขยายในปัจจุบันจะกลายเป็นเหมือนแอปพลิเคชันในขณะที่ยังสามารถแสดงเนื้อหาต่าง ๆ และวิดีโอได้ ซึ่งผู้ใช้จะสามารถกำหนดรูปแบบของบริการได้โดยตรง เหมือนที่แฮ็กเกอร์และบางเว็บไซต์ทำอยู่ในตอนนี้

5. 3D Graphic หรือ Metaverse

Web 3.0 จะมีลักษณะของการประมวลผลแบบไฮบริดระหว่างข้อมูลจากโลกจริงและโลกเสมือน ด้วยจุดมุ่งหมายเพื่อทำให้เส้นแบ่งระหว่างโลกจริงและโลกเสมือนเชื่อมกันได้แบบไร้รอยต่อ ซึ่งกราฟิกแบบสามมิติ หรือ โลกเสมือนจริง จะสามารถเชื่อมต่อกับโลกแห่งความจริงได้อย่างแนบเนียนใน Web 3.0 มักใช้การออกแบบสามมิติในเว็บไซต์และบริการต่าง ๆ กราฟิก 3 มิติ จะมีส่วนสำคัญในการสร้างประสบการณ์ใหม่อันน่าตื่นเต้นให้แก่ผู้คน ซึ่งไม่ใช่แค่ในเกมแบบ 3 มิติ แต่ยังรวมถึงธุรกิจและอุตสาหกรรมในด้านอื่น ๆ เช่น ธุรกิจด้านสุขภาพ อสังหาริมทรัพย์ ตลอดจนการเที่ยวชมพิพิธภัณฑ์ และการช้อปปิ้ง เป็นต้น

เทคโนโลยีการประมวลผลที่ขอบเครือข่าย (Edge Computing)

การมาถึงของ web 3.0 กำลังเปลี่ยนผ่านศูนย์ข้อมูลแบบเดิมที่เคยมีให้โยกย้ายออกไปที่ Edge Computing ที่มีความปลอดภัยสูงกว่าบนอุปกรณ์ต่าง ๆ ที่เราใช้งาน ทั้งสมาร์ทโฟน คอมพิวเตอร์ เครื่องใช้ไฟฟ้า และรถยนต์ ซึ่งว่ากันว่าจะมีการสร้างและใช้ข้อมูลมากกว่า160 เท่าในปี 2568 เมื่อเทียบกับปี 2553

โครงข่ายแบบกระจายอำนาจ ( Decentralized Network)

โครงข่ายข้อมูลแบบกระจายอำนาจ หรือ แนวคิดของการกระจายศูนย์ ที่เริ่มมีการพูดถึงอย่างกว้างขวางในยุคนี้ หรือเรียกอีกอย่างว่า “เว็บไซต์กระจายศูนย์” (Decentralized Web) ซึ่งไม่จำเป็นต้องพึ่งพาตัวกลางที่เป็นผู้เก็บข้อมูลและดำเนินการเพียงผู้เดียว ซึ่งจะช่วยให้ผู้ผลิตข้อมูลต่าง ๆ สามารถขายหรือแลกเปลี่ยนข้อมูลของตนโดยไม่สูญเสียความเป็นเจ้าของ ไม่ถูกคุกคามความเป็นส่วนตัว หรือต้องพึ่งพาคนกลาง ซึ่งหมายความว่าผู้บริโภคจะมีอำนาจในการควบคุมข้อมูลของตน และสามารถเข้าสู่ระบบต่าง ๆ บนโลกออนไลน์ได้อย่างปลอดภัยผ่านทางอินเทอร์เน็ต

(2015 – ปัจจุบัน) WEB 4.0 ( เทคโนโลยีมีสมอง ) ยุคน้ีถูกนำมาพัฒนาต่อยอดเพื่อลดบทบาทของมนุษย์ และเพิ่มศักยภาพของมนุษย์ในการใช้ความคิดเพื่อข้ามขีดจำกัด โดยจะใช้ชื่อยุคนี้ว่ายุค Machine-to-Machine เช่นสามารถสั่งงานเปิด/ปิดเครื่องใช้ไฟฟ้าผ่าน Application มีการใช้เทคโนโลยีซิมูเลชั่น Simulation จำลองสถานการณ์ วางแผนสถานการณ์ต่าง ๆโดยไม่ต้องเดินทางไปถึงสถานที่นั้นจริง
ซึ่งในยุคนี้จะมีการจดจำลักษณะการใช้งานของแต่ละบุคคล เพื่อให้สามารถค้นหา หรือ สืบค้นข้อมูลได้ตรงกับผู้ใช้มากขึ้น ซึ่งการพัฒนาเว็บไซต์ในปัจจุบันจะพัฒนาในรูปแบบที่สามารถใช้งานร่วมกับสมาร์ทโฟนได้

WEB 4.0 ซึ่งมีการเรียกกันอีกอย่างว่า “A Symbiotic web” คือ เว็บที่ทำงานแบบ Artificial Intelligence (AI) ที่ฉลาดมากยิ่งขึ้น คอมพิวเตอร์สามารถคิดได้ มีความฉลาดมากขึ้น ในการอ่านทั้งเนื้อหา ข้อความ และรูปภาพ หรือวีดีโอ สามารถที่จะตอบสนองหรือตัดสินใจได้ว่าจะ load ข้อมูลอะไร จากไหน จึงจะให้ประสิทธิภาพดีที่สุดมาให้ผู้ใช้งานก่อนก่อน และนอกจากนี้ยังมีรูปแบบการนำมาแสดงที่รวดเร็ว เว็บ 4.0 จะทำให้เว็บ หรือข้อมูลต่าง ๆ สามารถทำงานได้แทบจะทุก อุปกรณ์หรืออาจจะช่วยระบุตัวตนที่แท้จริงของผู้ใช้ได้

Web 4.0 ยุคเอเจนต์ปัญญาประดิษฐ์ (AI Agents)

Web 4.0 เป็นแนวคิดเกี่ยวกับเว็บยุคถัดจาก Web 3.0 ที่ยังไม่มีคำนิยามและมาตรฐานที่ยอมรับร่วมกัน (Aghaei et al., 2012; Ibrahim, 2021) งานวิจัยมักอธิบายว่าเป็น "เว็บแบบพึ่งพาอาศัยกัน (Symbiotic Web)" ที่มนุษย์และเครื่องจักรทำงานร่วมกันอย่างชาญฉลาด โดยมีเอเจนต์ปัญญาประดิษฐ์ (AI Agents) ช่วยเรียนรู้ ตัดสินใจ และดำเนินงานแทนผู้ใช้ (Ibrahim, 2021)

Aghaei et al. (2012) สรุปวิวัฒนาการของเว็บเป็น 4 รุ่น คือ Web 1.0 เว็บเพื่อการรับรู้ (อ่านอย่างเดียว) Web 2.0 เว็บเพื่อการสื่อสาร Web 3.0 เว็บเพื่อความร่วมมือ และ Web 4.0 เว็บเพื่อการบูรณาการที่มีปฏิสัมพันธ์อย่างชาญฉลาด

ตัวอย่างทิศทางที่เห็นในปัจจุบัน ได้แก่ ผู้ช่วย AI ที่ค้นหา เปรียบเทียบข้อมูล และดำเนินการบางอย่างแทนผู้ใช้ รวมถึงเครื่องมือเขียนโปรแกรมที่ทำงานแบบเอเจนต์ (ดูหัวข้อ 2.21) ทั้งนี้ข้อสังเกตนี้เป็นการตีความของผู้เขียนเอกสาร ไม่ใช่นิยามมาตรฐาน ผู้เรียนจึงควรใช้คำว่า Web 4.0 อย่างระมัดระวัง และระบุแหล่งอ้างอิงทุกครั้ง

ข้อควรระวัง: Web 3.0 กับ Web3 ไม่ใช่สิ่งเดียวกัน

• Web 3.0 ในความหมายเดิม คือเว็บเชิงความหมาย (Semantic Web) ที่ทำให้ข้อมูลบนเว็บมีความหมายที่เครื่องประมวลผลได้ (Berners-Lee et al., 2001)

• Web3 ในความหมายปัจจุบัน คือแนวคิดเว็บแบบกระจายอำนาจบนเทคโนโลยีบล็อกเชน ซึ่ง Gavin Wood เสนอเมื่อปี 2557 (ค.ศ. 2014) (Kharpal, 2022)

• สองคำนี้มักถูกใช้สลับกันในสื่อทั่วไป จึงควรระบุความหมายทุกครั้งที่ใช้

2.20.1 ส่วนขยาย VS Code และโครงสร้างโฟลเดอร์โครงงานเว็บ

ส่วนขยาย (Extensions) ของ Visual Studio Code ช่วยให้เขียนเว็บสะดวกขึ้น ติดตั้งได้จากแท็บ Extensions (กด Ctrl+Shift+X บน Windows หรือ Cmd+Shift+X บน macOS) แล้วค้นหาตามชื่อ ส่วนขยายที่ใช้บ่อยในรายวิชานี้ ได้แก่

• Live Server: เปิดหน้า HTML ผ่านเซิร์ฟเวอร์จำลองขนาดเล็กและรีเฟรชเบราว์เซอร์ให้อัตโนมัติเมื่อบันทึกไฟล์ ใช้กับ HTML, CSS และ JavaScript ได้ แต่ไม่ประมวลผล PHP (ไฟล์ PHP ต้องเปิดผ่าน Apache ของ XAMPP หรือ MAMP)

• Prettier - Code Formatter: จัดรูปแบบโค้ดให้เป็นระเบียบโดยอัตโนมัติ

• Auto Rename Tag: เมื่อแก้ชื่อแท็กเปิด จะแก้ชื่อแท็กปิดให้พร้อมกัน

• PHP Intelephense: ช่วยเติมโค้ดและตรวจข้อผิดพลาดของภาษา PHP (ใช้ในบทที่ 7 และ 8)

2.20.2 พื้นฐาน Git และ GitHub สำหรับงานเว็บ

Git เป็นโปรแกรมควบคุมเวอร์ชัน (Version Control System) ที่บันทึกประวัติการแก้ไขไฟล์ ช่วยให้ย้อนกลับไปยังฉบับก่อนหน้า เปรียบเทียบการเปลี่ยนแปลง และทำงานร่วมกันเป็นทีมได้ ส่วน GitHub เป็นบริการบนเว็บที่เก็บคลังโค้ด (Repository) ของ Git ไว้ออนไลน์ ทั้งสองเป็นคนละอย่างกัน Git ทำงานในเครื่อง ส่วน GitHub เป็นที่เก็บและแบ่งปันโค้ดบนอินเทอร์เน็ต ตรวจว่าเครื่องมี Git หรือไม่ด้วยคำสั่งด้านล่าง (ถ้าไม่มีให้ติดตั้งจากเว็บไซต์ git-scm.com) และตั้งชื่อกับอีเมลสำหรับบันทึกประวัติเพียงครั้งเดียว

git --version

git config --global user.name "ชื่อของคุณ"

git config --global user.email "อีเมลของคุณ"

ขั้นตอนพื้นฐานในโฟลเดอร์ของโครงงานเว็บ: git init สร้าง Repository ในโฟลเดอร์ (ตัวเลือก -b main ตั้งชื่อสาขาหลักเป็น main ใช้ได้กับ Git รุ่น 2.28 ขึ้นไป รุ่นเก่ากว่าให้สั่ง git init แล้ว git branch -M main) git status ดูสถานะไฟล์ git add เตรียมไฟล์ที่จะบันทึก git commit บันทึกเป็นการเปลี่ยนแปลงหนึ่งครั้งพร้อมข้อความอธิบาย และ git log --oneline ดูประวัติ

cd my-website

git init -b main

git status

git add .

git commit -m "เพิ่มหน้าแรกและไฟล์ CSS"

git log --oneline

ไฟล์ .gitignore ระบุไฟล์ที่ Git ไม่ต้องติดตามหรือไม่ควรส่งขึ้นที่เก็บ โดยเฉพาะไฟล์ที่มีรหัสผ่านหรือค่าตั้งลับ เช่น ไฟล์ตั้งค่าการเชื่อมต่อฐานข้อมูล ตัวอย่างเนื้อหาไฟล์ .gitignore:

.DS_Store

node_modules/

.env

wp-config.php

การส่งโค้ดขึ้น GitHub: (1) สมัครบัญชีที่ github.com (2) กดเครื่องหมาย + แล้วเลือก New repository ตั้งชื่อ เลือกสาธารณะ (Public) หรือส่วนตัว (Private) ถ้าจะส่งโครงงานที่มีไฟล์อยู่แล้ว ไม่ต้องเลือกสร้างไฟล์ README ตั้งแต่แรก มิฉะนั้นต้องดึงไฟล์นั้นลงเครื่องก่อน (3) ผูก Repository ในเครื่องกับ GitHub แล้วส่งขึ้นด้วยคำสั่งต่อไปนี้ (แทนที่ชื่อผู้ใช้ด้วยชื่อบัญชี GitHub ของตน)

git remote add origin https://github.com/ชื่อผู้ใช้/my-website.git

git push -u origin main

การยืนยันตัวตน: GitHub ยกเลิกการใช้รหัสผ่านบัญชีสำหรับคำสั่ง Git แล้ว (ตามเอกสารของ GitHub) หากส่งผ่าน HTTPS ให้ใส่ Personal Access Token ในช่องรหัสผ่านเมื่อระบบถาม หรือใช้ตัวช่วยจำข้อมูล (Credential Helper) เช่น Git Credential Manager หรือเลือกใช้ SSH key แทน ห้ามเผยแพร่ Token หรือเขียนไว้ในโค้ด

คำสั่งที่ใช้ประจำเมื่อทำงานต่อเนื่อง:

git status # ดูไฟล์ที่เปลี่ยน

git add . # เตรียมไฟล์ทั้งหมดเพื่อบันทึก

git commit -m "อธิบายสิ่งที่แก้"

git push # ส่งขึ้น GitHub

git pull # ดึงการแก้ไขล่าสุดจาก GitHub มาที่เครื่อง

git switch -c feature-x # สร้างและสลับไปสาขาใหม่

git switch main # กลับไปสาขา main

ใน VS Code ทำขั้นตอนเหล่านี้ผ่านแท็บ Source Control (กด Ctrl+Shift+G บน Windows หรือ Cmd+Shift+G บน macOS) ซึ่งแสดงไฟล์ที่เปลี่ยน มีช่องใส่ข้อความ commit และปุ่มส่งขึ้นที่เก็บ ข้อควรระวัง: Repository สาธารณะทุกคนมองเห็นได้ ห้าม commit รหัสผ่านฐานข้อมูล ไฟล์ .env หรือ wp-config.php ผู้เขียนทดสอบคำสั่งในหัวข้อนี้ด้วย Git 2.54.0 กับที่เก็บปลายทางจำลองในเครื่อง ไม่ได้ส่งขึ้น GitHub จริง

การสั่งงาน AI ให้ช่วยเขียนโปรแกรมได้อย่างมีประสิทธิภาพ มีเทคนิคสำคัญที่นักพัฒนาต้องเรียนรู้ ดังนี้:
• การระบุบริบทที่ชัดเจน (Clear Context): แจ้งเวอร์ชันของภาษาและสภาพแวดล้อม เช่น "เขียนคำสั่ง JavaScript (ES6) สำหรับตรวจสอบความถูกต้องของอีเมล"
• การขอให้อธิบายโค้ด (Code Explanation): สั่งให้ AI อธิบายขั้นตอนการทำงานของโค้ดที่ซับซ้อน เช่น "ช่วยอธิบายการทำงานของ Regular Expression นี้ทีละส่วน"
• การค้นหาและแก้ไขข้อผิดพลาด (Debugging): ส่งข้อความแจ้งเตือนข้อผิดพลาด (Error Message) ร่วมกับโค้ดต้นเหตุ เพื่อให้ AI วิเคราะห์สาเหตุและแนวทางแก้ไข
• การปรับปรุงโครงสร้างโค้ด (Refactoring): สั่งให้ AI ปรับปรุงโค้ดเดิมให้อ่านง่ายขึ้น ลดความซ้ำซ้อน และทำงานได้รวดเร็วขึ้นตามหลักการ Clean Code

2.21.3 ข้อพึงระวัง จริยธรรม และความปลอดภัยในการใช้ AI เขียนโปรแกรม

แม้ว่า AI จะช่วยประหยัดเวลาได้อย่างมหาศาล แต่นักพัฒนาเว็บไซต์ต้องยึดถือแนวทางปฏิบัติอย่างเคร่งครัด:
1. ห้ามคัดลอกโค้ดโดยไม่เข้าใจ: นักศึกษาต้องสามารถอธิบายการทำงานและตรรกะของโค้ดทุกบรรทัดได้ด้วยตนเอง การพึ่งพา AI โดยขาดความเข้าใจพื้นฐานจะทำให้ไม่สามารถพัฒนาทักษะการคิดเชิงคำนวณ (Computational Thinking) ได้
2. ตรวจสอบช่องโหว่ความมั่นคงปลอดภัย (Security Auditing): โค้ดที่สร้างโดย AI อาจมีช่องโหว่ความปลอดภัย เช่น ขาดการกรองข้อมูลนำเข้า (Input Sanitization) นำไปสู่ปัญหา SQL Injection หรือ XSS นักพัฒนาต้องตรวจสอบโค้ดอย่างละเอียดก่อนนำไปใช้งานจริงเสมอ
3. ปัญหาลิขสิทธิ์และความเป็นส่วนตัว: ต้องไม่ส่งคีย์ลับ รหัสผ่านฐานข้อมูล (Database Credentials) หรือข้อมูลส่วนบุคคลของลูกค้า เข้าไปในระบบ AI

2.21.4 กรอบคำสั่งมาตรฐานสำหรับ AI Pair Programming (Prompt Formula)

การนำ AI Coding Assistants เช่น GitHub Copilot หรือ Cursor เข้ามาเป็นคู่คิดในการพัฒนาโปรแกรม (GitHub, 2024; Google Cloud, 2024) ควรกำหนดบทบาทให้นักศึกษาเป็น "Lead Architect / Driver" ผู้คุมทิศทางและตรรกะ ส่วน AI เป็นเพียง "Navigator" ผู้เสนอแนะทางเลือก โดยมีกรอบคำสั่งมาตรฐาน (Prompt Formula) ดังนี้:

"Context: We are developing a RESTful API backend for a student registration system in PHP 8. / Task: Create a Controller method to validate input data and insert a new student record into MySQL using Prepared Statements. / Constraints: Ensure PDPA compliance, sanitize all inputs, use strict types, and return JSON responses with HTTP 201 on success or HTTP 400 on error."

2.23 พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA) สำหรับนักพัฒนาเว็บ

กฎหมายคุ้มครองข้อมูลส่วนบุคคลของไทยคือพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (พระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล, 2562) ประกาศในราชกิจจานุเบกษาเมื่อวันที่ 27 พฤษภาคม 2562 หมวดที่ว่าด้วยสิทธิของเจ้าของข้อมูลและหน้าที่ของผู้ควบคุมข้อมูลมีผลหลังประกาศหนึ่งปี และมีการเลื่อนการบังคับใช้ต่อมา จนมีผลเต็มรูปแบบวันที่ 1 มิถุนายน 2565 (ตามแหล่งข้อมูลทุติยภูมิ ควรตรวจประกาศที่เกี่ยวข้องในราชกิจจานุเบกษา) นักพัฒนาเว็บมักทำงานให้องค์กรที่เป็นผู้ควบคุมข้อมูลส่วนบุคคล (Data Controller) หรือทำหน้าที่เป็นผู้ประมวลผลข้อมูล (Data Processor) ซึ่งมีหน้าที่ต่างกัน จึงควรเข้าใจหลักการต่อไปนี้ (เลขมาตราอ้างตามพระราชบัญญัติ):

• ฐานทางกฎหมายและความยินยอม (มาตรา 19, 24): ต้องมีฐานทางกฎหมายในการเก็บ ใช้ หรือเปิดเผยข้อมูลส่วนบุคคล กรณีใช้ความยินยอม ต้องขอก่อนหรือขณะเก็บ แจ้งวัตถุประสงค์ด้วยถ้อยคำชัดเจนและแยกจากเรื่องอื่น และผู้ใช้ถอนความยินยอมได้ทุกเมื่อ ส่วนกรณีที่เก็บได้โดยไม่ต้องขอความยินยอม เช่น จำเป็นเพื่อปฏิบัติตามสัญญาหรือเพื่อปฏิบัติตามกฎหมาย (มาตรา 24) ดังนั้นไม่ใช่ทุกกรณีที่ต้องมีแบนเนอร์ขอความยินยอม

• การแจ้งรายละเอียด (มาตรา 23): ต้องแจ้งก่อนหรือขณะเก็บ ได้แก่ วัตถุประสงค์ ข้อมูลที่เก็บและระยะเวลาเก็บ ประเภทของผู้ที่อาจได้รับข้อมูล ช่องทางติดต่อผู้ควบคุมข้อมูล และสิทธิของเจ้าของข้อมูล ในทางปฏิบัติมักแสดงเป็นหน้านโยบายความเป็นส่วนตัว (Privacy Notice) ที่เข้าถึงได้จากทุกหน้า

• ใช้ตามวัตถุประสงค์ที่แจ้งและเก็บเท่าที่จำเป็น (มาตรา 21, 22): ออกแบบฟอร์มและตารางฐานข้อมูลให้เก็บเฉพาะข้อมูลที่จำเป็นต่อวัตถุประสงค์ และไม่นำไปใช้ต่างจากที่แจ้งไว้ เว้นแต่แจ้งวัตถุประสงค์ใหม่และได้รับความยินยอมหรือกฎหมายอนุญาต

• สิทธิของเจ้าของข้อมูล (เช่น มาตรา 30, 33): ผู้ใช้ขอเข้าถึงและขอสำเนาข้อมูลของตนได้ และขอให้ลบ ทำลาย หรือทำให้ไม่สามารถระบุตัวตนได้ในกรณีที่กฎหมายกำหนด ระบบจึงควรออกแบบให้ค้นหา ส่งออก และลบข้อมูลของผู้ใช้รายคนได้

• มาตรการรักษาความมั่นคงปลอดภัย (มาตรา 37 (1)): ผู้ควบคุมข้อมูลต้องจัดให้มีมาตรการที่เหมาะสมเพื่อป้องกันการสูญหาย การเข้าถึง ใช้ เปลี่ยนแปลง หรือเปิดเผยโดยไม่ชอบ กฎหมายไม่ได้กำหนดเทคนิคเฉพาะ แต่แนวปฏิบัติที่เรียนในรายวิชานี้เข้ากับหลักการนี้ เช่น แฮชรหัสผ่านด้วย password_hash() ใช้ HTTPS ใช้ Prepared Statements และกำหนดสิทธิ์เข้าถึงตามบทบาท

• การแจ้งเหตุละเมิดข้อมูล (มาตรา 37 (4)): เมื่อเกิดการละเมิดข้อมูลส่วนบุคคล ต้องแจ้งสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคลโดยไม่ชักช้า และหากทำได้ต้องภายใน 72 ชั่วโมงนับแต่ทราบเหตุ เว้นแต่การละเมิดนั้นไม่น่าจะมีความเสี่ยงต่อสิทธิและเสรีภาพของบุคคล และหากมีความเสี่ยงสูงต้องแจ้งเจ้าของข้อมูลด้วย ตามหลักเกณฑ์ที่คณะกรรมการประกาศกำหนด

• ข้อมูลจราจรทางคอมพิวเตอร์: การเก็บข้อมูลจราจรเป็นหน้าที่ตามพระราชบัญญัติว่าด้วยการกระทำความผิดเกี่ยวกับคอมพิวเตอร์ พ.ศ. 2550 (มาตรา 26) (พระราชบัญญัติว่าด้วยการกระทำความผิดเกี่ยวกับคอมพิวเตอร์, 2550) ซึ่งกำหนดให้ผู้ให้บริการเก็บรักษาข้อมูลจราจรไว้ไม่น้อยกว่า 90 วัน เป็นหน้าที่ของผู้ที่เข้าข่ายเป็น "ผู้ให้บริการ" ตามนิยามของกฎหมายนั้น ไม่ใช่นักพัฒนาเว็บทุกคน (ข้อนี้ตรวจจากแหล่งข้อมูลทุติยภูมิ ควรตรวจตัวบทฉบับแก้ไขล่าสุดก่อนนำไปใช้)

หมายเหตุ: เนื้อหาส่วนนี้เป็นความรู้พื้นฐานเพื่อการเรียนการสอน ไม่ใช่คำปรึกษาทางกฎหมาย ตัวบทฉบับภาษาไทยในราชกิจจานุเบกษาเป็นฉบับที่มีผลทางกฎหมาย ส่วนฉบับภาษาอังกฤษของกระทรวงดิจิทัลเพื่อเศรษฐกิจและสังคม (Ministry of Digital Economy and Society, 2019) เป็นคำแปลที่ไม่เป็นทางการ พระราชบัญญัติกำหนดโทษทั้งทางแพ่ง ทางอาญา และโทษปรับทางปกครอง (เช่น ปรับทางปกครองไม่เกิน 5 ล้านบาทสำหรับบางฐานความผิด ตามมาตรา 84)

สรุป

การเขียนโปรแกรมบนเว็บอาศัยองค์ประกอบพื้นฐานที่เชื่อมโยงกันอย่างเป็นระบบ ตั้งแต่เทคโนโลยีฝั่งผู้ใช้ (Client-Side) อันได้แก่ HTML, CSS, JavaScript และเฟรมเวิร์กสมัยใหม่ (React, Vue, Angular) ตลอดจนเทคโนโลยีฝั่งเซิร์ฟเวอร์ (Server-Side) เช่น PHP, Node.js, ASP.NET Core และการจัดการข้อมูลผ่านระบบฐานข้อมูลทั้งแบบเชิงสัมพันธ์ (RDBMS: MySQL) และแบบ NoSQL การติดต่อสื่อสารระหว่างระบบดำเนินผ่าน Web Service และ RESTful API โดยมีสถาปัตยกรรม MVC ช่วยจัดระเบียบโครงสร้างโค้ดให้บำรุงรักษาง่าย นอกจากนี้ในยุคปัจจุบัน สภาพแวดล้อมการพัฒนาได้ก้าวหน้าด้วยโปรแกรมแก้ไขโค้ดที่ทรงพลังอย่าง VS Code และการนำผู้ช่วยอัจฉริยะ (AI Coding Assistants) เข้ามาช่วยในการพัฒนาและตรวจทานโค้ดอย่างมีประสิทธิภาพ โดยนักพัฒนาต้องยึดมั่นในความถูกต้อง ความมั่นคงปลอดภัย และจริยธรรมทางวิชาชีพอย่างสม่ำเสมอ

แบบฝึกหัด

คำชี้แจง: จงทำแบบฝึกหัดต่อไปนี้เพื่อทบทวนความรู้ความเข้าใจ

1. จงอธิบายความแตกต่างระหว่างการทำงานของ Client-Side Script และ Server-Side Script พร้อมยกตัวอย่างภาษาที่ทำงานในแต่ละฝั่งมาอย่างละ 2 ภาษา

2. จงเปรียบเทียบจุดเด่นและข้อจำกัดระหว่างระบบจัดการฐานข้อมูลเชิงสัมพันธ์ (RDBMS) เช่น MySQL กับฐานข้อมูล NoSQL เช่น MongoDB พร้อมระบุว่าระบบงานประเภทใดควรเลือกใช้ฐานข้อมูลแบบใด

3. สถาปัตยกรรม Model-View-Controller (MVC) (ศุภชัย สมพานิช, 2565) มีบทบาทอย่างไรในการพัฒนาโปรแกรมบนเว็บ และช่วยส่งเสริมการทำงานร่วมกันเป็นทีมของนักพัฒนาอย่างไร

4. จงอธิบายความแตกต่างระหว่าง Web Service กับ RESTful API พร้อมยกตัวอย่างรูปแบบข้อมูล (เช่น JSON หรือ XML) ที่นิยมใช้ในการแลกเปลี่ยนข้อมูลในปัจจุบัน

5. เฟรมเวิร์กสำหรับ Front-end ยุคใหม่ (เช่น React, Vue.js, Angular) เข้ามาแก้ไขปัญหาหรือข้อจำกัดใดของการพัฒนาเว็บด้วย Vanilla JavaScript แบบดั้งเดิม

6. จงอธิบายเหตุผลที่ทำให้ Visual Studio Code (VS Code) กลายเป็นโปรแกรมแก้ไขโค้ด (Code Editor) ที่ได้รับความนิยมสูงสุดในหมู่นักพัฒนาเว็บทั่วโลก พร้อมยกตัวอย่างส่วนขยาย (Extensions) ที่มีประโยชน์ 2 ตัวอย่าง

7. ปัญญาประดิษฐ์ช่วยเขียนโค้ด (AI Coding Assistants เช่น GitHub Copilot, Gemini Code Assist, Cursor) มีหลักการทำงานอย่างไร และสามารถช่วยเพิ่มผลิตภาพในการพัฒนาเว็บได้อย่างไรบ้าง

8. หากนักพัฒนานำโค้ดที่สร้างโดย AI มาใช้งานโดยไม่มีการตรวจสอบ อาจส่งผลกระทบต่อความมั่นคงปลอดภัย (Security) และลิขสิทธิ์ของซอฟต์แวร์อย่างไร จงอธิบายแนวทางป้องกัน
